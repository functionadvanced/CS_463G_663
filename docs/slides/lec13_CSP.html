Constraint Satisfaction Problems

A constraint satisfaction problem (CSP) describes what a solution must satisfy, separately from how we find it.

Piece Meaning Exam-scheduling example
Variable X_i A decision to make The time slot for exam i
Domain D_i Allowed values for X_i Slots \{1,2,3\}
Constraint A rule on allowed combinations Conflicting exams use different slots

A solution assigns a domain value to every variable and satisfies every constraint.

The same framework describes Sudoku digits, map colors, and queen positions.

Connect to Lectures 11 and 12: a queens candidate can be scored by conflicts, but here we state the non-attack requirements directly. A basic CSP is a feasibility problem, not necessarily an optimization problem. Source: original Lecture 13 Beamer material and AIMA’s constraint satisfaction chapter. Suggested pacing for the 50-minute meeting: exam modeling and propagation about 18 minutes; types, feasibility, and the triangle example about 8; Sudoku about 13; lab activity and queens connection about 8; summary about 3. Detailed consistency algorithms and backtracking heuristics are reserved for Lectures 14 and 15.

A Small Exam Schedule

Exams A, B, C, D each take one of three nonoverlapping slots.

  • Shared students prevent these pairs from overlapping: AB, AC, BD, CD.
  • Assume enough rooms for any exams that may run together.

Which decisions need variables? Do rooms need to be represented?

Answer: one variable per exam, whose value is its time slot. Rooms do not need variables under this explicit capacity assumption. A uses only slot 1; B cannot use 3; C has no availability restriction; D cannot use 1. Enough rooms does not remove shared-student conflicts. Source: original course scheduling example from the existing Lecture 13.

Variables, Domains, and the Graph

Let X_A be A’s slot, with remaining domain D_A; use the same notation for B, C, and D.

A constraint graph has one node per variable. An edge joins two variables constrained together; here, each edge means different slots.

There is no B-C edge: B and C may share a slot. This is not a search tree or a travel map.

The graph encodes X_A != X_B, X_A != X_C, X_B != X_D, X_C != X_D. Node labels abbreviate the variables. Unary availability restrictions are stored in domains and need no graph edge. There is also no A-D edge. This simple graph view applies to binary constraints; constraints involving more variables need an additional representation or a decomposition. Source: AIMA constraint graphs and the course exam model.

Complete and Consistent

Complete: all variables have values. Consistent: assigned values are in their domains and violate no constraint among them.

Tuples below list (X_A,X_B,X_C,X_D) in that order.

Assignment Complete? Consistent?
X_A=1,\ X_B=2 No Yes
X_A=1,\ X_B=1 No No: AB
(1,2,2,2) Yes No: BD, CD
(1,2,2,3) Yes Yes

Only the last row is a solution. A consistent partial assignment is not yet a solution.

Reveal answers one row at a time. Partial means at least one variable remains unassigned. In the third row, B and C sharing 2 is allowed; D sharing their value violates both incident constraints. Consistency of a partial assignment does not assert that a completion exists; the later triangle gives a counterexample. Source: course exam example and standard CSP terminology.

A Domain-Reduction Trace

Constraint propagation removes values ruled out by the constraints. A singleton domain contains just one value, so that value is forced.

X_A=1 removes 1 from D_B and D_C.

X_B=2 removes 2 from D_D.

X_D=3 removes 3 from D_C. Solution: (1,2,2,3).

Gold marks the variable causing the current reduction; teal marks affected neighbors. Initially: {1}, {1,2}, {1,2,3}, {2,3}. After A: {1}, {2}, {2,3}, {2,3}. After B: {1}, {2}, {2,3}, {3}. After D: {1}, {2}, {2}, {3}. All four inequalities hold at the end. Every deduction was forced by the original requirements, and this example has a unique solution. Propagation does not solve every CSP. Lecture 14 formalizes consistency. Source: course scheduling model.

One More Conflict

A student now takes both B and C. Add the rule X_B\ne X_C, keeping the same availability restrictions.

Can all requirements still be satisfied?

No. A, B, and D force slots 1, 2, and 3. C has no remaining value: D_C=\varnothing.

The new diagonal B-C edge is pink. The previous deductions forcing A=1, B=2, D=3 remain valid after adding a constraint. C must now differ from all three. This proves infeasibility, not just a failed attempt. A fourth slot for C, with C allowed to use it, would repair the model; ignoring the new shared student would not. If an empty domain instead follows a tentative search choice, it rules out that branch, not automatically the entire original problem. Source: course exam example.

Unary, Binary, and Global Constraints

The arity of a constraint is the number of variables it involves.

Kind Example Meaning
Unary X_A=1 A rule on one variable
Binary X_A\ne X_B A rule on two variables
Global \operatorname{AllDifferent}(X_1,\ldots,X_9) A structured rule on a collection

\operatorname{AllDifferent}(X,Y,Z) requires every pair to differ:

X\ne Y\quad\land\quad X\ne Z\quad\land\quad Y\ne Z.

Do X\ne Y and Y\ne Z alone imply all three are different? No: (X,Y,Z)=(1,2,1) satisfies both.

The symbol land means logical AND. Global is not simply an arity of three; it names a structured constraint over a collection, potentially of varying size. AllDifferent is logically equivalent to all pairwise inequalities, but a specialized propagation algorithm may use its global structure more effectively. Source: AIMA CSP formulations.

A Consistent Start Can Still Fail

A separate example has three exams, all conflicting with each other, and only slots 1 and 2. Assign X_A=1.

Consistent so far: X_A=1 violates no constraint among assigned exams. Can we assign B and C too, while satisfying every constraint?

No. B and C would both need slot 2, but they conflict. Starting with X_A=2 fails symmetrically.

This is a new three-variable model, not a modification of the four-exam example. Each initial domain is {1,2}. With only A assigned, no binary constraint has two assigned endpoints, so the partial assignment is consistent. There is nevertheless no extension. At the completely unassigned state, each value even has support on each individual edge, yet there is no joint solution; leave formal arc consistency to Lecture 14. Source: course triangle example.

Feasibility and Preferences

Kind Meaning Scheduling example
Hard constraint Must be satisfied No simultaneous exams for a shared student
Soft preference Ranks feasible assignments Prefer fewer exams in slot 3

For n exams with slots X_1,\ldots,X_n, one possible objective is

\min_X \sum_{i=1}^{n}\mathbf{1}\{X_i=3\}\quad\text{subject to all hard constraints}.

The indicator is 1 when exam i uses slot 3, and 0 otherwise.

A basic CSP seeks feasibility. Constraint optimization also compares feasible assignments.

The objective counts exams, not unique students. X denotes the vector of exam slots. This is a general scheduling extension; our four-exam instance has only one feasible assignment, so a preference cannot select a different solution without changing that model. A lower objective never excuses a hard-constraint violation. Source: existing lecture’s feasibility-versus-preference distinction.

Sudoku as a CSP

Fill the 9\times9 grid with digits 1 through 9, preserving the given clues.

  • Variables: the 81 cells, named A1 through I9.
  • Domains: \{1,\ldots,9\} for blanks; a singleton for each clue, such as D_{\mathrm{A1}}=\{5\}.
  • Constraints: each row, column, and 3\times3 block contains all nine digits exactly once.

Clues are fixed values, not suggestions. The initial puzzle is a partial assignment.

The puzzle is the same as the original Wikipedia-derived course image and the existing Sudoku notebook. The notebook uses zero-based indices. We include all 81 cells and use singleton clue domains. An equivalent formulation can make only blanks variables and treat clues as constants. There are 30 clues and 51 blanks. With nine cells and domain 1 through 9, AllDifferent implies that every digit occurs exactly once. Source: original Lecture 13 Beamer Sudoku example and sudoku.ipynb.

Rows, Columns, and Blocks

A Sudoku unit is a row, column, or block. Each unit has an \operatorname{AllDifferent} constraint.

The same cell also participates in its column constraint.

And its block constraint. There are 27 units: 9 rows, 9 columns, 9 blocks.

A3 is gold throughout. Other cells in the displayed unit are teal. Each peer’s given digit forbids that same digit at A3. A peer is another cell sharing at least one unit; overlapping memberships are not separate variables. A cell has 20 distinct peers in standard Sudoku. The unit view avoids an unreadably dense graph. Source: original Lecture 13 row, column, and subgrid diagrams, consolidated into an animated draw.io figure.

Candidate Values for A3

Exclude digits assigned to A3’s peers: its row, column, or block.

Which values remain in D_{\mathrm{A3}}?

D_{\mathrm{A3}}=\{1,\ldots,9\}\setminus\{3,5,6,7,8,9\}=\{1,2,4\}.

Remaining candidates are not guaranteed to extend to a solution.

Row A excludes 3,5,7. Column 3 excludes 8. The upper-left block excludes 3,5,6,8,9. Repeated excluded digits are removed once. Set-minus means remove the listed values. Do not insert the known solution’s 4 simply because the puzzle is familiar; this local test leaves three candidates. Source: original puzzle and the candidate example in sudoku.ipynb.

Forced Values and Propagation

Using the same clues, the center cell E5 has only candidate 5.

E2 shares E5’s row and currently allows \{2,5\}. What follows?

Set E5 = 5, remove 5 from its peers, then E2 = 2 is forced. A deduction can trigger another deduction.

E5’s row excludes 1,3,4,8; its column excludes 1,2,6,7,8,9; its center block excludes 2,3,6,8. Their union leaves only 5. E2 originally allows 2 or 5. The figure highlights these two cells and their shared row; a full propagation operation also updates E5’s other column and block peers. These are forced deductions, not guesses. An unresolved empty domain signals contradiction; a singleton is forced. Source: original course Sudoku puzzle.

Search and Propagation

If propagation stalls, search may choose a variable and try a remaining value. A3’s local candidates illustrate possible branches:

  • Propagate: make deductions forced by current constraints.
  • Backtrack: undo a tentative choice if its branch fails, then try another.

For m blanks, there are at most 9^m complete fillings before constraints are used. This puzzle has m=51; pruning avoids exploring many of them.

The branches are alternatives, not simultaneous assignments or solved puzzles. Another variable may be a better choice; ordering heuristics belong to Lecture 15. The 9^m count is a loose count of complete fillings, not measured runtime or a tight solver bound. Fixed variable order gives at most nine value branches per level; do not multiply by the remaining variable count and explore many orders of identical assignments. Backtracking must restore all branch-specific domain changes. Source: original Beamer search and propagation content, with the assignment-count distinction made explicit.

Modeling Practice: A Lab Schedule

Experiments P, Q, R each take one of three equal, nonoverlapping slots \{1,2,3\}.

Write the variables, domains, and constraints. Give one valid schedule and one invalid schedule, with a reason.

Let students formulate the model before revealing the next slide. Each experiment lasts exactly one slot. Equal, nonoverlapping slots make precedence a strict inequality on slot indices. Nothing says P and R share equipment; do not invent that constraint. Source: existing Lecture 13 lab-scheduling practice.

Lab Schedule: A Formulation

X_P,X_Q,X_R are the slots. D_P=D_Q=\{1,2,3\} and D_R=\{2,3\}.

Constraints: X_P<X_Q and X_Q\ne X_R.

Assignment (X_P,X_Q,X_R) Why invalid?
(2,1,3) P does not finish before Q starts
(1,2,2) Q and R need the shared equipment together

Multiple solutions are allowed; do not invent additional constraints.

The figure shows two valid schedules, not every solution. (2,3,2) is also valid because P and R may coincide: the only equipment conflict is Q-R. This catches an unstated AllDifferent assumption. Domains encode R’s unary restriction directly. Source: original course lab activity.

N-Queens as a CSP

As in Lecture 12, let Q_i be the queen’s row in column i, with domain D_i=\{1,\ldots,N\}.

For each pair of columns i<j:

Different rows: Q_i\ne Q_j.

No diagonal attack: |Q_i-Q_j|\ne|i-j|.

One variable per column already enforces one queen in each column.

Same encoding, different formulation: instead of rewarding fewer conflicts, the CSP requires zero conflicts.

The figure uses N=4 for readability; equations apply to general N. It is a satisfying example, not the conflicted eight-queens chromosome from Lecture 12. Diagonal attack means the absolute row difference equals the absolute column difference. The unrestricted row-vector encoding needs row inequalities; a permutation enforces distinct rows structurally. A Boolean variable per square would need additional cardinality constraints such as exactly one queen per column. Source: AIMA N-queens CSP formulation and the previous lecture’s representation.

Takeaways

Modeling question What to specify
What decisions must be made? Variables
What values may each decision take? Domains, including fixed values
Which combinations are allowed? Every required constraint
What counts as success? A complete assignment satisfying all constraints
  • Consistency so far does not guarantee a valid completion.
  • Propagation removes impossible values; search handles unresolved choices.
  • A solver answers the model we give it, including its assumptions.
