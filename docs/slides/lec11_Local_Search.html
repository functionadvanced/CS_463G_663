Searching for a Configuration

Local search keeps a current candidate and moves among nearby candidates. The goal is often a good final configuration.

An objective function scores each candidate. We will minimize a cost c(s): lower is better.

In systematic search we kept a frontier of alternatives and often stored parent links to recover a path. The single-state local methods here keep one current candidate, sometimes with a best-so-far record. They can use little memory, but they may stop without finding a goal or global optimum. A complete candidate may violate constraints. It is not necessarily a valid solution. Four queens is the smaller version of eight queens. Queens attack along rows, columns, and diagonals. The sliding puzzle remains a path-finding task, and the scheduled GUI demonstrates legal moves rather than implementing a local-search solver. Source: AIMA local search section and the original Lecture 11 Beamer source.

Queens: State, Cost, and Neighborhood

  • State s: one queen per column. Each list entry gives that queen’s row.
  • Cost c(s): pairs sharing a row or diagonal, counting each pair once. A solution has c(s)=0.
  • Neighborhood N(s): move one queen to a different row in its column.

With 4 queens, how many neighbors? With 8 queens? 4\times3=12 and 8\times7=56.

Rows are numbered top to bottom, columns left to right. Q denotes a queen. Starting with all queens present makes every state a complete assignment, even when queens attack. A pair attacks if it shares a row or if its row difference equals its column difference in absolute value. Sharing a column is impossible in this representation. There are six distinct pairs among four queens, so this starting cost is 6, not 12. Each of n queens has n-1 alternative rows, giving n(n-1) distinct neighbors. A systematic construction can instead add queens one at a time and backtrack when constraints fail. We use four queens to make the same eight-queens representation visible at a readable size. Source: AIMA n-queens local-search formulation. Worked boards are original course examples.

A Greedy Queen-Move Trace

Hill climbing chooses a best immediate neighbor. For our cost, it moves downhill and accepts only a strict decrease.

Move column 2: cost 6 to 3. Choose one of the best moves if tied.

Move column 1: cost 3 to 1. Recompute neighbors from the new board.

Move column 4: cost 1 to 0. This run succeeds, but other starting states can get stuck.

At each step, consider all 12 neighbors, not just the selected queen. The chosen successor has minimum neighbor cost: 3, then 1, then 0. Equal best neighbors exist, so this is one valid greedy trace rather than a uniquely prescribed path. The gold queen marks the queen just moved. After the first move the three attacking pairs are columns (1,3), (1,4), and (3,4). After the second move only columns 3 and 4 attack. The last board [2,4,1,3] solves four queens. Source: original course example using the AIMA neighborhood.

Hill-Climbing Pseudocode

s is the current state, N(s) its neighbors, and K a move budget. LOWEST_COST chooses a neighbor with smallest c.

HILL_CLIMB(s, K)
for step in 1 .. K:
if EMPTY(N(s)): return s
n <- LOWEST_COST(N(s))
if c(n) >= c(s): return s
s <- n
return s

Stopping means no strict local improvement or budget exhausted. Check the returned cost before calling it a solution.

This is steepest-ascent hill climbing expressed as cost minimization, also called steepest descent. It scans the neighborhood and chooses a best candidate. A streaming scan can retain only the best neighbor rather than materializing the whole set. Memory savings are therefore implementation dependent. Ties between equally good successors may be broken arbitrarily. The >= test prevents sideways moves, so a finite state space cannot cycle through accepted states. A known goal cost such as zero in n-queens permits an additional early stop. For general optimization, a low cost does not certify a global optimum. Source: AIMA hill-climbing algorithm, adapted to a cost and finite budget.

A Local Minimum Can Stop the Search

A local minimum is no worse than its neighbors. A global minimum has the lowest cost in the entire state space below.

From A, move to B: cost 8 to 5.

From B, move to C, cost 2. Then stop: B costs 5, D costs 4. The better state G is beyond a worsening move.

The graph is the whole state space for this toy problem. Edges define neighbors, and the numbers inside circles are state costs, not edge costs. The vertical placement only helps show lower and higher cost. C is a strict local minimum because both its neighbors have higher cost. G is the global minimum. If the goal were cost 0, hill climbing from A would fail to find an existing solution. With a score to maximize, the equivalent trap is a local maximum. Plateaus and Restricted Moves

A plateau has equal-cost neighbors. A ridge for a score, or narrow valley for a cost, may point between the allowed move directions.

Limited sideways moves can cross a plateau but may cycle. A different neighborhood can help, when the problem permits it.

In the left graph, the current state is the first 2. Strict improvement halts immediately. Two equal-cost moves would reach the third 2, which has a lower-cost neighbor. A sideways-move budget or cycle detection prevents indefinite wandering, but does not guarantee success. In the right grid, lower numbers are better. From the bottom-right 3, up and left both give 5. A diagonal move would give 2, but it is outside this chosen neighborhood. This demonstrates how an apparently favorable direction may not be an available step. A narrow valley can produce slow zigzag progress or traps in a discrete neighborhood. We cannot arbitrarily introduce illegal puzzle moves. Source: AIMA plateaus and ridges, with original discrete course examples.

Random Restarts

Start again from a new random candidate, run hill climbing, and keep the best result across runs.

A restart changes the starting region. Use a time or restart budget: finite attempts do not guarantee success.

A start at C repeats the same failure under the same strict rule. A restart samples a new state, which may lie in a different basin of attraction. In this chain, E descends to F then G. There is still no guarantee that a random restart picks E or another successful start. If independent runs each succeed with probability p, k runs succeed at least once with probability 1-(1-p)^k. This estimate depends on independence and a common success probability. It is not necessary to compute p in practice to apply a budget. Source: AIMA random-restart hill climbing.

Simulated Annealing: Crossing a Cost Barrier

Annealing heats a material and cools it. Simulated annealing borrows the temperature idea: it sometimes accepts a worse candidate.

Suppose we accept C to D: cost rises from 2 to 4.

Then propose E, cost 3. It improves on D, though C was better.

Then F, cost 1, improves the best record.

Then G, cost 0. This is one possible random trajectory, not a guaranteed route.

All comparisons use the current state, not the best state previously seen. E3 improves on current D4 and is accepted even though the earlier C2 was better. The gold circles mark previously visited states, and teal marks the current state. At C, the move to D is worsening and requires a probabilistic acceptance decision. Later steps also depend on which neighbor is proposed. The next slide quantifies the acceptance probability. The physical analogy is settling into low-energy configurations; avoid claiming that annealing always increases a material’s strength. Source: original Lecture 11 annealing motivation and AIMA simulated annealing. Graph and trajectory are original course examples.

The Annealing Acceptance Rule

For current state s and proposed neighbor n, let \Delta=c(n)-c(s). Temperature T>0 controls acceptance of a cost increase.

P(\text{accept})= \begin{cases} 1, & \Delta\le0,\\ \exp(-\Delta/T), & \Delta>0. \end{cases}

For a proposed cost increase from 2 to 4, \Delta=2. Draw u uniformly from [0,1) and accept if u<P(\text{accept}).

Temperature T Probability for \Delta=2 With u=0.30
4 e^{-0.5}\approx0.607 Accept
1 e^{-2}\approx0.135 Reject
0.25 e^{-8}\approx0.000335 Reject

P denotes probability. exp(z) is the exponential function e to the power z. The uniform random number is a fresh draw for each proposal; the fixed u=0.30 only illustrates how temperature changes the decision for the same draw. Improvements and equal-cost moves have probability one under this rule. As T decreases, a fixed positive delta has smaller acceptance probability. Larger cost increases are also less likely at a fixed temperature. The argument -delta/T is negative for worsening moves. If T is zero or negative, stop before evaluating the exponential. Source: AIMA simulated-annealing acceptance rule. Numerical probabilities are rounded.

Simulated-Annealing Pseudocode

K limits proposals. schedule(t) gives temperature at iteration t. COPY preserves a separate best-state snapshot.

ANNEAL(s, K, schedule)
best <- COPY(s)
for t in 0 .. K - 1:
T <- schedule(t)
if T <= 0: break
n <- RANDOM_NEIGHBOR(s)
delta <- c(n) - c(s)
p <- 1 if delta <= 0 else EXP(-delta / T)
if UNIFORM(0, 1) < p:
s <- n
if c(s) < c(best): best <- COPY(s)
return best

The current state may get worse. Update best only when its cost improves.

RANDOM_NEIGHBOR returns one valid candidate without mutating the current state, and UNIFORM(0,1) returns a sample in [0,1). This pseudocode assumes a nonempty neighborhood, as in n-queens; a general implementation should stop if no proposal is available. The conditional assignment evaluates EXP only for positive delta. Rejected proposals leave s unchanged but still consume one iteration and cool the schedule. A known optimal target cost permits early stopping. COPY is essential when a mutable board might otherwise share storage with best. The output is the best state observed within the budget, not a guaranteed global optimum. Source: AIMA acceptance rule, with explicit best-state tracking and budget added for the course.

Cooling and the Best-State Record

A cooling schedule lowers temperature: T(t)=T_0\rho^t, with starting temperature T_0>0 and cooling factor 0<\rho<1.

  • Cooling too fast can freeze the search near a local minimum.
  • Cooling slowly spends more of the budget exploring. Test several random seeds.

Current cost 4, best seen 2. Which state should we return? The saved state with cost 2.

T0 is the starting temperature, rho the multiplicative cooling factor, and t the iteration count starting at zero. A rho closer to 1 cools more slowly for a fixed starting temperature and iteration count. Temperature has to be interpreted relative to the scale of cost differences. Multiplying the objective by 100 while keeping T fixed greatly reduces acceptance of worsening moves. The plotted sequence is an illustrative accepted-state history, not output from the notebook. At accepted move 4, current cost is 4 but best cost is 2. Save the state, not just its numeric score. Finite practical schedules do not guarantee the global optimum. Source: AIMA cooling discussion and original course trace.

Takeaways

Method Move rule Main limitation
Hill climbing Take a best strictly improving neighbor Can stop above the global minimum
Random restarts Try new starts, keep the best result Repeated work, limited attempts
Simulated annealing Sometimes accept a worse candidate Depends on proposals and cooling

Define the state, cost, and neighborhood precisely. Check whether an algorithm returns the current state or the best state it has seen.
