The Room Is Clean. Should We Stop?

The vacuum is in A. Its sensor says clean. It cannot see B.

What should the agent remember before deciding to stop?

Begin with a show of hands: stop, move, or not enough information? The two worlds are shown to the class, not to the agent. This reprises percept versus world state without repeating the Lecture 2 definitions.

Specify the Task with PEAS

PEAS = Performance measure, Environment, Actuators, Sensors.

Component Our two-room vacuum
Performance measure Keep rooms clean; avoid unnecessary actions.
Environment Rooms A and B, dirt, and the vacuum’s location.
Actuators Move left, move right, suck dirt, or do nothing.
Sensors Current location and dirt in the current room only.

Describe success and available information before choosing an algorithm.

PEAS is a task specification, not an agent algorithm. The evaluator may know more than the agent’s sensors reveal. Ask why seeing the current room is not the same as seeing the whole world.

[Sources]

  • Russell and Norvig, Artificial Intelligence: A Modern Approach, Chapter 2, task environments. https://aima.cs.berkeley.edu/4th-ed/slides-pdf/chapter02.pdf

One World, Explicit Assumptions

  • Two connected rooms: A on the left, B on the right.
  • A move or a cleaning action takes one step.
  • Sensors are accurate; actions always succeed.
  • Dirt does not reappear in the baseline world.
  • NoOp means “no operation”: stay idle for one step.

Which assumption makes “I cleaned this room earlier” useful now?

The assumptions define the teaching simulator, not all real vacuums. No new dirt plus deterministic cleaning lets the agent infer that a previously cleaned room remains clean. We will deliberately break the no-new-dirt assumption later.

Four Ways to Choose an Action

Agent design Central question
Simple reflex What rule matches my current percept?
Model-based reflex What is the state, given my history and model?
Goal-based What actions can reach a desired state?
Utility-based Which outcome is preferable, including tradeoffs?

These describe decision mechanisms, not a ranking of intelligence.

Memory and models also appear in goal-based and utility-based agents. Learning is not a fifth rung that replaces the other designs: it can improve their components. Preview the distinctions here and use the next slides to unpack them.

[Sources]

  • Russell and Norvig, AIMA, Chapter 2, structure of agents. https://aima.cs.berkeley.edu/4th-ed/slides-pdf/chapter02.pdf

Simple Reflex: Match a Rule

Current percept only. No stored history and no look-ahead.

  • If the current room is dirty: Suck.
  • Otherwise: move to the other room.

A simple rule can work well when the current percept is enough.

Rules can be supplied by a designer or learned; simple reflex describes what information is used for action selection. Here the second rule deliberately does not know whether the other room is already clean.

[Sources]

  • Russell and Norvig, AIMA, Chapter 2, simple reflex agents. Original course diagram.

A Reflex Agent Can Keep Moving

Suppose both rooms are already clean. The same rule keeps firing.

Can the agent safely stop based only on “my current room is clean”?

No, not with this sensor and without additional information: the other room might still be dirty. The issue is not that every reflex policy oscillates, but that this particular policy does, and current-room cleanliness does not establish the global goal.

Model-Based: Maintain Internal State

A model describes how actions and the environment change the world.

Internal state is an estimate of the world, not direct access to hidden facts.

For this vacuum, the internal state records whether A and B are known to be clean, dirty, or still unknown. The model says Suck succeeds and dirt does not reappear. Other model-based agents may track probabilities rather than a single estimated state.

[Sources]

  • Russell and Norvig, AIMA, Chapter 2, model-based reflex agents. Original course diagram.

Goal-Based: Consider Future States

Goal: both rooms are clean. Start in A with both rooms dirty.

  • A goal test says whether a state is acceptable.
  • Search or planning can find actions that reach it.

These are illustrative candidate plans, not a full search tree. A goal-based agent uses a model to consider future consequences. A goal test accepts both outcomes; a search algorithm may additionally minimize path cost. Goal-based does not mean oblivious to cost. This introduces the need for search without teaching BFS early.

[Sources]

  • Russell and Norvig, AIMA, Chapter 2, goal-based agents. Original course example and diagram.

Utility-Based: Compare Acceptable Outcomes

A utility function assigns a numerical preference to outcomes.

Plan from A Reaches the goal? Non-idle actions
Suck, Right, Suck Yes 3
Right, Suck, Left, Suck Yes 4
  • If each action uses energy, prefer the first plan, all else equal.
  • With uncertainty, compare expected utility.
  • Tradeoffs can include cleanliness, energy, time, and risk.

Reaching a goal and choosing a preferable outcome are different questions.

Utility represents preferences, not the agent literally feeling happiness. There is no need to introduce expectation notation yet. A goal plus path cost already expresses a simple preference; utility is a more general way to compare outcomes and uncertainty.

[Sources]

  • Russell and Norvig, AIMA, Chapter 2, utility-based agents. Plan lengths are derived from the course example.

Learning Can Improve Any Design

  • Learn better rules from experience.
  • Learn a better model of action outcomes.
  • Learn to predict utility more accurately.
  • Use feedback to update the decision-making components.

Remembering a room’s condition is not, by itself, learning better rules.

Our memory-based Python agent will update state but will not change its rules or learn a model. In the classic learning-agent decomposition, the performance element chooses actions, the critic supplies feedback, the learning element improves components, and the problem generator encourages informative experience. Mention these verbally if students ask; formal learning algorithms come later.

Which Component Is Missing?

Situation Needed addition
The vacuum forgets rooms it has already cleaned. Internal state
It needs an action sequence that cleans both rooms. Goal-directed planning
Two plans work, but one uses much less energy. A preference / cost criterion
It should improve its rules after repeated mistakes. Learning

Can a single agent use all four additions?

Reveal one answer at a time. Yes: the categories describe components and mechanisms that can be combined. This is a quick check before translating the ideas into Python.

The Simulator Owns the World

class VacuumWorld:
    def __init__(self, start="A", dirt=None):
        self.position = start
        self.dirt = {"A": True, "B": True} if dirt is None else dict(dirt)

    def perceive(self):
        room = self.position
        return room, self.dirt[room]
  • True means dirty; False means clean.
  • The simulator stores both rooms’ conditions.
  • The agent receives only (current_room, current_dirt).

World state belongs to the simulator. Percepts are the agent’s input.

Actions Change the World

The apply method belongs to VacuumWorld.

def apply(self, action):
    if action == "Suck":
        self.dirt[self.position] = False
    elif action == "Left":
        self.position = "A"
    elif action == "Right":
        self.position = "B"
    elif action != "NoOp":
        raise ValueError(f"Unknown action: {action}")

NoOp leaves the world unchanged. The outer loop still advances time.

The policies only choose Right from A and Left from B. The toy transition function maps Left to A and Right to B; an unnecessary move at an edge would leave the position unchanged and still incur the action cost. Suck is deterministic in this model.

Agent 1: A Simple Reflex Rule

class ReflexAgent:
    def act(self, percept):
        room, dirty = percept
        if dirty:
            return "Suck"
        return "Right" if room == "A" else "Left"
  • Dirty here? Clean here.
  • Otherwise, go to the other room.
  • No record of what happened before.

What will it do after it has cleaned both rooms?

Agent 2: Remember What We Know

class MemoryAgent:
    def __init__(self):
        self.seen = {"A": None, "B": None}

    def act(self, percept):
        room, dirty = percept
        self.seen[room] = dirty
        if dirty:
            self.seen[room] = False  # Predict successful cleaning.
            return "Suck"
        if all(value is False for value in self.seen.values()):
            return "NoOp"
        return "Right" if room == "A" else "Left"

None means unknown. Stop only when both rooms are known to be clean.

This is a model-based reflex agent: it applies fixed rules to maintained state, rather than searching over future action sequences. The predicted update on line 9 relies on the known model that cleaning succeeds. The test uses “is False” deliberately: “not value” would also accept None and incorrectly treat an unobserved room as clean. The display comment is shortened from the runnable source; the executable statements are identical.

Connect Sensing, Acting, and Scoring

Start with a fresh world, an empty trace, and score = 0.0.

for step in range(1, steps + 1):
    percept = world.perceive()
    action = agent.act(percept)
    world.apply(action)
    clean = sum(not value for value in world.dirt.values())
    effort = int(action != "NoOp")
    score += clean - 0.25 * effort
    trace.append((step, percept, action, clean, effort))

The evaluator can inspect both rooms. The agent cannot.

This is the baseline loop in run_agent, without the optional new-dirt event used later. No score or complete world-state dictionary is passed into act. The demo keeps running after NoOp so both agents are evaluated for the same horizon. Highlight input, action, evaluation, then logging.

Non-idle actions 8 3
Action penalty 2.00 0.75

14 - 0.25(8) = 12, \qquad 14 - 0.25(3) = 13.25

If the action penalty were zero, would these two scores differ?

They would tie at 14. This links to Lecture 2: the performance measure shapes what counts as better. This example is not a proof that more memory always improves performance or that this particular agent is optimal in all environments.

Change the World, Recheck the Model

At the start of step 5, room A becomes dirty again.

  • The reflex agent is in A and immediately cleans it.
  • The memory agent is idle in B and does not observe A.
  • Its remembered fact “A is clean” is now stale.
Same 8-step scoring rule Reflex Memory
Final clean rooms 2 1
Total score 12.00 9.25

Memory helps only when its updates and assumptions fit the environment.

Discuss periodic reinspection or expiring old observations as possible responses, not guaranteed optimal fixes. The agent would need a different environment model and perhaps a tradeoff between checking cost and missed dirt.

Design Exercise: A Battery-Limited Vacuum

Battery capacity: 6 units. Each move or Suck costs 1 unit. Recharge at A restores all 6 in one step; NoOp costs no energy. Dirt can reappear. Sensors report location, current-room dirt, and battery level.

  1. Specify PEAS, including recharging at A.
  2. What should the agent remember?
  3. Which decision mechanisms should it combine?
  4. Find a case where “clean whenever dirty” fails.

Allow small groups to work, then compare designs. Assume the layout is known, NoOp costs no battery, and Recharge is available only at A and restores capacity in one step. One example: starting full at A, the agent reaches dirty D with 3 units left. Cleaning costs 1, leaving only 2 units for the 3 moves back to the dock. No code or optimal-policy derivation is required.

One Possible Design

  • PEAS: sustained cleanliness without getting stranded; four rooms and a dock; move, Suck, NoOp, Recharge; local dirt, location, and battery sensors.
  • Internal state: room map, last observations, observation ages, and battery level.
  • Goal and planning: complete useful cleaning trips and return to the dock.
  • Preference: compare cleanliness gains, energy costs, and stale information.

At D with 3 units left, cleaning would leave too little energy to return to A.

An explicit safety check can reserve enough energy for a return trip before committing to an action. With deterministic one-unit moves, distance to the dock gives the needed reserve; uncertainty would need additional margin or a different model. Treat avoiding stranding as a constraint, not merely a tiny penalty that could be outweighed. Learning could improve estimates of how often rooms become dirty, but is not required for an initial design.

Takeaways

  • PEAS specifies the task before implementation.
  • Rules, state, goals, and utility answer different questions.
  • Learning can improve the components of an agent.
  • Evaluate agents under the same conditions.
  • Recheck the design when its assumptions change.
