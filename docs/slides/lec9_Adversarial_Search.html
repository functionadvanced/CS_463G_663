The Opponent Chooses a Reply

UCS and A* choose a route through a state space. In a game, another player controls some of the choices.

Your move Opponent’s possible replies Worst outcome for you
A Payoffs 3, 12, or 8 3
B Payoffs 2, 4, or 6 2

Which move would you choose if your opponent always selects your lowest payoff?

Choose A: its worst outcome is the best available. The payoff 14 is possible, but you cannot force it.

Which Games Fit Minimax?

Our model: two players take turns, each sees the full state, and each move has a known result.

Property Meaning Outside today’s model
Deterministic No random transition Dice rolls
Perfect information Both players observe the state Hidden cards
Zero-sum One player’s gain is the other’s loss Shared or independent rewards
Finite game tree Every line eventually ends Play without a termination rule

Tic-tac-toe fits this model. MAX seeks high utility; MIN seeks low utility, measured from MAX’s viewpoint.

Finite is an assumption for exact recursive minimax here, not a claim about all games. General games may include chance, hidden information, simultaneous moves, multiple players, or cycles. Game rules must resolve repetition or other termination conditions when those occur. Game theory is the broader study of strategic interaction. Source: course Lecture9 and AIMA adversarial search chapter.

Utility from MAX’s Viewpoint

  • MAX = X: prefer +1 to 0 to -1.
  • MIN = O: prefer -1 to 0 to +1.
  • The score’s meaning stays the same at every level.

At an O turn, choose the smallest X score. Do not change the sign just because the turn changes.

In a zero-sum model, O’s own utility is the negative of X’s. We can therefore store only X’s score. Terminal scores are stipulated by the rules; the values3,12,8 in the abstract example use a different utility scale. Do not add edge costs as in UCS or A*. A utility of0 here means an actual draw, not an unevaluated state.

Minimax Values

Let V(s) be the outcome from state s when both players choose optimally.

V(s)= \begin{cases} U(s), & \text{if }s\text{ is terminal},\\[0.35em] \max\limits_{a\in A(s)} V(\operatorname{Result}(s,a)), & \text{if MAX moves},\\[0.35em] \min\limits_{a\in A(s)} V(\operatorname{Result}(s,a)), & \text{if MIN moves}. \end{cases}

  • At a terminal state, read the outcome.
  • At a decision state, back up a child’s value using the player to move.

Search downward to discover outcomes; propagate values upward to compare moves.

A(s) abbreviates ACTIONS(s), and U(s) abbreviates UTILITY(s). The same fixed MAX viewpoint is used in all three cases. This recurrence describes exact minimax on a finite game tree. Source: AIMA adversarial search chapter and Berkeley CS188 minimax notes.

Return a Move, Not Just a Value

Result Meaning
Value: 3 Best worst-case payoff
Action: A Move to play now

The score tells us how good a position is. The selected action tells us what to do.

a^*\in\arg\max_{a\in A(s)}V(\operatorname{Result}(s,a)).

Record the action whenever you find a better child value. If values tie, either tied move is minimax-optimal.

This root formula assumes it is MAX’s turn. At MIN’s root use argmin. A strict greater-than update keeps the first move among ties; the next pseudocode makes that rule explicit. The highlighted line is one possible continuation under optimal play, not a complete contingent strategy.

A Strategy Handles Every Reply

After choosing a move, MAX must respond to the move MIN actually makes.

Object What it specifies
Fixed action sequence One predetermined line of play
Strategy A move for each MAX decision state that may arise
Minimax decision The next move at the current state

In our example, choosing A guarantees at least 3. If MIN instead chooses the leaf worth 12, MAX receives 12.

Minimax protects against the strongest opponent. It does not assume every opponent will actually play optimally.

With perfect play by both sides the root value is exactly3. Against an arbitrary legal opponent, a minimax strategy guarantees at least3 in this example. It may not exploit a predictable weak opponent as aggressively as a model tailored to that opponent. For a longer game, one can compute an entire contingent strategy or recompute the best next action after every observed reply. A minimax guarantee is not a guarantee of winning; a position may have value0 or a negative value.

Minimax Pseudocode: Evaluate a State

RESULT returns a new state with the next player to move. This version searches to terminal states.

VALUE(s)
if TERMINAL(s): return UTILITY(s)
if PLAYER(s) == MAX:
v <- -infinity
for a in ACTIONS(s):
v <- max(v, VALUE(RESULT(s, a)))
else: # MIN moves
v <- +infinity
for a in ACTIONS(s):
v <- min(v, VALUE(RESULT(s, a)))
return v

Explore children depth first. Return a value only after evaluating all legal alternatives at that node.

No depth parameter appears in exact VALUE: the stopping condition is terminal. The code assumes a finite game tree and at least one legal action in every nonterminal state. For a game with passing, a pass must be represented as a legal action. Terminal utility always refers to MAX. The loop accumulators use opposite infinities so they also handle all-negative MAX values or all-positive MIN values correctly. Source: standard minimax recurrence, rewritten as course pseudocode.

Minimax Pseudocode: Choose an Action

Precondition: the state is nonterminal and MAX moves next.

CHOOSE_MOVE(s)
best_value <- -infinity; best_action <- None
for a in ACTIONS(s):
value <- VALUE(RESULT(s, a))
if value > best_value:
best_value <- value
best_action <- a
return best_action

At the root: evaluate A:3, B:2, C:2. Keep A and return the action A.

The recursive function computes scores. The outer loop remembers the move that produced the best score.

The strict comparison retains the first action among equally valued alternatives. The successor of a MAX move normally belongs to MIN; the state carries that turn, so the caller need not toggle a separate flag. This is the counterpart of retaining a parent/action in UCS and A*: computing a numeric value alone is insufficient to act. Standard tic-tac-toe utilities are finite.

Why Minimax Is Correct

Assume a finite tree, correct game rules, and exact terminal utilities.

  1. At a leaf: the utility is the actual outcome.
  2. At a MAX node: if the child values are correct, MAX can choose the largest.
  3. At a MIN node: MIN can choose the smallest, so MAX cannot count on anything larger.

Apply this argument repeatedly from the leaves to the root. Each backed-up value is correct once its children are correct.

The chosen strategy guarantees MAX its minimax value. That value may represent a win, draw, or loss.

This is induction on subtree height. At MAX nodes there exists a maximizing action achieving the backed-up bound. At MIN nodes every legal reply has value at least the minimum, and an optimal MIN can choose a reply attaining that minimum. Hence exact minimax provides the best worst-case guarantee. The theorem relies on searching to actual terminal states; arbitrary heuristic cutoffs lose that guarantee.

Search Cost

Let b be the branching factor and m the maximum number of remaining plies.

Time

A full tree has

1+b+\cdots+b^m=O(b^m).

For b=3, m=10: 59,049 leaves and 88,573 total nodes.

Memory

Depth-first evaluation keeps the active recursion path and pending siblings.

  • O(bm) if each call stores its children.
  • O(m) if successors are generated one at a time.

You can evaluate a tree without storing all of it. The number of positions examined still grows exponentially.

These are search-node/record counts with state representation costs treated as fixed. The O(m) version assumes a constant-size successor iterator and no table retaining prior states. Eagerly storing the entire tree would instead take exponential memory. The full-tree formula assumes b greater than1; b=3 is a constructed branching example, not a claim about all tic-tac-toe positions. Tic-tac-toe branching decreases as squares fill, and some games end early. Standard depth-first minimax complexity follows AIMA.

Terminal Utility and Cutoff Evaluation

Large games may require stopping before a terminal state. Let d count plies still available.

VALUE_LIMITED(s, d):
    if TERMINAL(s): return UTILITY(s)
    if d == 0:     return EVAL(s)
    # Otherwise use the same MAX / MIN recursion,
    # calling VALUE_LIMITED(RESULT(s, a), d - 1).
Leaf type Returned score
Terminal position Exact outcome U(s)
Nonterminal depth cutoff Estimated value \operatorname{EVAL}(s)

Unlike A*’s remaining-cost estimate, EVAL estimates game value. Heuristic errors can change the move; optimal play is no longer guaranteed.

Check TERMINAL before d==0 so a terminal state at the cutoff receives its exact utility. EVAL always uses the same MAX viewpoint. Minimax over heuristic leaves is exact for those supplied leaf scores but is not guaranteed optimal in the actual game. Unlike A*’s admissible remaining-cost heuristic, there is no admissibility condition introduced here that restores exact play. Keep this as a bridge; Lecture10 covers practical cutoff methods and alpha-beta. Reference: https://inst.eecs.berkeley.edu/~cs188/textbook/games/minimax.html#322-evaluation-functions.

Check Your Understanding

1. A MAX node has child values -7,-2,-5. What is its value?

-2. MAX chooses the largest value even when every outcome is negative.

2. Can you stop after finding a winning leaf somewhere in the tree?

Not in general. MIN may choose another reply before you reach that leaf.

3. Does a minimax value of 0 mean the program did not finish?

No. With our tic-tac-toe utilities, exact minimax value 0 means a draw under optimal play.

Allow about2 minutes. For question2, distinguish an arbitrary winning descendant from a root action whose backed-up value is the maximum possible utility. An implementation can stop once it has proved a maximum attainable root value, but merely seeing one winning leaf is insufficient. For question3, exact utility0 and an unfinished computation are different concepts. At a heuristic cutoff, a score0 is only an estimate.

Takeaways

  • A game state includes whose turn it is.
  • MAX takes the maximum; MIN takes the minimum, using one utility viewpoint.
  • Back up values, then retain the action that achieves the root’s best value.
  • Exact minimax gives the best worst-case guarantee, but its time cost is exponential.
