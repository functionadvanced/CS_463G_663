Images as Inputs

A convolutional neural network (CNN) learns local patterns in grid-like data, including images.

The MNIST dataset, short for Modified National Institute of Standards and Technology, contains handwritten digits.

  • Each grayscale image has 28\times28 pixels, or brightness values.
  • The target is one digit label from 0 to 9.
  • Our notebook predicts one digit per image using ten output scores.

The digit pixels are reused unchanged from the saved KNN notebook figure in Lecture 24. The layout crops its old prediction headings, so they cannot be mistaken for CNN results. The MNIST expansion is the customary short name of the dataset; its creators modified the original NIST data. Source: https://docs.pytorch.org/vision/stable/generated/torchvision.datasets.MNIST.html. The notebook’s one-digit classification task is separate from Homework 5. Do not preview the homework’s paired-digit construction here.

Local Connections and Shared Weights

A fully connected, or dense, layer connects every input value to every output unit. Flattening rearranges the pixels into a vector, without deleting their values.

CNNs build in two structural choices:

Idea Meaning for an image
Local connections A unit examines a small neighboring patch of pixels.
Weight sharing The same learned coefficients examine patches at different positions.

A filter is a small array of weights. One 3\times3 grayscale filter has 9 weights and 1 bias, reused across the image.

Training learns these shared weights. Their gradient contributions accumulate across the positions where the filter operates.

Flattening is an invertible rearrangement when the original shape is known. The issue is that an unrestricted dense layer does not enforce two-dimensional locality or shared weights. Convolution imposes those structural assumptions. The count of ten parameters is for one ordinary single-input-channel filter with a bias, independent of image size. It is not the parameter count of an entire CNN. Source: the supplied Spring 2025 CNN Beamer source, revised manually, and https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html.

Kernels, Patches, and Feature Maps

A kernel, also called a filter, is a small array of weights. A patch is the input window under it. A feature map records the resulting value at each position.

For this arithmetic example, fix the displayed kernel and use bias b=0. Slide it one pixel at a time, with no extra border pixels.

These constructed grids retain the numerical example from the original Beamer lecture. The numbers are neither measured image intensities nor trained CNN weights. Actual CNN training learns kernel weights and biases using backpropagation. The central coefficient -4 and the four neighboring coefficients 1 make a local contrast filter. Do not call every kernel an edge detector or imply that all learned filters have this fixed form.

A Filter Moving Across the Image

At each position, multiply matching entries and add. We number rows and columns starting at 0.

O_{0,0}=2+0+3+2-4\cdot1=3.

O_{0,1}=0+1+1+1-4\cdot3=-9.

Repeat for every valid patch. The kernel coefficients stay the same.

The compact arithmetic shows only the four nonzero neighboring contributions and the center term. Coefficients at the patch’s four corners are zero. Frame one uses top=2, left=0, right=3, bottom=2, center=1. Frame two uses top=0, left=1, right=1, bottom=1, center=3. The final feature map is [[3,-9,3],[-4,3,3],[3,-3,3]]. The teaching example has one input channel, stride 1, no padding, and zero bias. The PyTorch Conv2d cross-correlation convention agrees with this calculation.

The Convolution Rule

For one input channel, a square f\times f kernel, and one-pixel steps:

O_{i,j}=b+\sum_{u=0}^{f-1}\sum_{v=0}^{f-1} I_{i+u,j+v}K_{u,v}.

  • I is the input, K the kernel, O the output map, and b a shared bias.
  • (i,j) locates the patch’s top-left corner.
  • (u,v) indexes an entry within the kernel, starting at (0,0).

The numerical example has f=3 and b=0.

Each output value is a small weighted sum. Backpropagation learns the kernel weights and bias just as it learns dense-layer parameters.

This formula assumes stride 1, no padding, dilation 1, and one input channel. The same formula works with implicit padded input values when padding is added. Strictly, applying the kernel without flipping it is cross-correlation. PyTorch and ordinary CNN terminology call this operation convolution. The distinction does not require changing the kernel or the numerical example. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html.

Stride and Padding

Stride s is the number of pixels moved per step. Padding p adds border values, here p rows or columns of zeros on every side.

  • Larger stride usually reduces the output’s height and width.
  • Padding lets filters cover boundary pixels and can preserve spatial size.

Stride is measured along both spatial dimensions in our square examples. The two outlined windows on the left are the first two positions in the top row for stride 2; two more windows start two rows lower. The right diagram illustrates padding itself, not a second stride-2 calculation. Its original input is 3 by 3 and its padded array is 5 by 5. The next slide separately calculates the convolution’s output dimensions. Source: the supplied Beamer stride/padding frames, redrawn and clarified.

Output Height and Width

For a square input with side n, kernel side f, stride s, and zero-padding width p, the output side is

n_{\mathrm{out}}=\left\lfloor\frac{n+2p-f}{s}\right\rfloor+1.

The floor \lfloor\cdot\rfloor rounds down. Count only full kernel windows.

Input side n Kernel side f Stride s Padding p Output side
5 3 1 0 3
5 3 2 0 2
28 3 1 1 28

Both notebook convolutions use the last row: spatial size stays 28\times28.

This is the usual convolution shape rule with dilation fixed at 1. Rectangular inputs apply the same rule separately to height and width. A padded width of p adds p entries to both sides, hence 2p. The 3-by-3 padded example on the preceding slide would give (3+2-3)/1+1=3 output entries per side for stride 1. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html, Shape section.

Channels and Multiple Filters

A channel is one value plane. Grayscale has one channel. RGB means red, green, blue, with three color channels.

Each output channel uses its own learned filter, covering all input channels in an ordinary convolution.

For C_{\mathrm{in}} input channels and C_{\mathrm{out}} output channels, an f\times f layer has C_{\mathrm{out}}(C_{\mathrm{in}}f^2+1) parameters, including biases.

The notebook’s first layer has 32(1\cdot3^2+1)=320 parameters and produces 32 feature maps.

The drawing illustrates the RGB case; the notebook instead starts with grayscale, so C_in=1. One ordinary filter has C_in separate f-by-f weight planes whose contributions are summed, plus one output-channel bias. There are C_out such filters. The count assumes groups=1, bias=True, and no separate normalization-layer parameters. Weight sharing makes this count independent of image height/width. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html.

ReLU After Convolution

ReLU, the rectified linear unit, applies \max(0,z) separately to each entry z.

  • Convolution computes weighted sums and biases.
  • ReLU adds a nonlinear transformation. It introduces no learned weights.
  • Applying ReLU leaves the tensor’s shape unchanged.

The figure applies ReLU to the exact completed toy convolution, not to a measured MNIST activation map. Stacking only affine transformations would still produce an affine transformation. ReLU enables a richer input/output mapping. This reconnects to Lecture 28. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.ReLU.html.

Pooling: A Smaller Feature Map

Pooling summarizes each small window. Max pooling keeps its largest value. Average pooling keeps its mean.

This separate example uses 2\times2 windows and stride 2, reducing 4\times4 to 2\times2. Pooling operates on each channel independently and learns no weights.

Pooling reduces spatial detail. It can soften sensitivity to small shifts, but a shifted image can still produce a different result.

The pooling input is a different constructed grid, matching the original Beamer example. The four window maxima are 6, 9, 7, and 8. Ordinary max/average pooling uses no learned parameters. Do not promise exact translation invariance or that pooling necessarily prevents overfitting. Modern CNNs can also downsample using strided convolution, so pooling is a common option rather than a universal requirement. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.MaxPool2d.html.

Feature Maps to Class Scores

Flattening rearranges each image’s feature maps into a vector. A fully connected (FC) layer, also called a dense layer, combines its entries.

For the notebook, 64\cdot14\cdot14=12{,}544 values enter the first FC layer.

The final ten logits are raw scores, one per digit 0 through 9. The predicted digit is the index of the largest score, called argmax.

The layer dimensions are taken directly from the existing CNN notebook. Flattening preserves each example and only rearranges its feature entries. The intermediate 128-unit layer uses ReLU. The architecture also has dropout, defined explicitly on the next slide before the full pipeline. Logits can be negative, need not sum to one, and are not probabilities. Softmax can convert them to probabilities when wanted for display; it does not change their argmax. Some CNN classifiers instead use global average pooling, so this flatten-and-dense head is our example, not a requirement for all CNNs.

The Notebook’s CNN

Dropout randomly zeroes some hidden activations during training. Our model uses a probability of 0.5 before its final layer.

Shapes in the diagram describe one image. PyTorch batches use order (B,C,H,W): batch size, channels, height, width.

The diagram follows CNN.ipynb exactly: Conv2d(1,32,3,stride=1,padding=1), ReLU, Conv2d(32,64,3,stride=1,padding=1), ReLU, MaxPool2d(2,2), flatten, Linear(641414,128), ReLU, Dropout(0.5), Linear(128,10). The two convolution outputs keep 28 by 28 spatial dimensions. Pooling changes that to 14 by 14. The batch dimension persists through flattening; it is not combined with the feature dimension. Dropout also rescales surviving activations during training. It acts as the identity in evaluation mode. Sources: the local CNN notebook and https://docs.pytorch.org/docs/stable/generated/torch.nn.Dropout.html.

Training and Evaluation

Cross-entropy is a classification loss that penalizes low probability for the correct class. PyTorch’s CrossEntropyLoss takes raw logits and integer digit labels, handling the probability calculation internally.

Control What it changes
model.train() Enables training behavior, including dropout.
loss.backward() and optimizer.step() Compute gradients, then update parameters.
model.eval() Disables dropout for ordinary prediction.
torch.no_grad() Stops recording gradient history. It does not disable dropout.

Use both evaluation mode and disabled gradient tracking for the notebook’s test pass. Keep test examples separate from model selection.

This revisits the mode/gradient distinction from Lecture 27 in the concrete CNN setting. The ten-class index targets have integer dtype, normally torch.int64. Do not apply softmax before the standard CrossEntropyLoss used by the notebook. For hard class targets, that loss combines log-softmax with negative log likelihood. Evaluation mode does not itself turn off autograd. no_grad remains a supported API; inference_mode is another option with stronger restrictions. Hyperparameter/architecture choices should use validation data before a final test evaluation. Source: https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html and https://docs.pytorch.org/docs/stable/generated/torch.nn.Dropout.html.

Quick Check

  1. Does moving a trained kernel to another patch create new weights?
  2. A 28\times28 input uses a 3\times3 kernel, stride 1, padding 0. What is the output side?
  3. Does torch.no_grad() switch off dropout?

1. No. Every position reuses the same learned weights and bias.

2. 26. (28-3)/1+1=26. Adding padding 1 would preserve side 28.

3. No. model.eval() controls dropout. Gradient tracking is a separate setting.

Takeaways

  • Convolution combines local connections with shared learned weights.
  • A feature map records one filter’s response across positions.
  • Stride and padding determine output height and width.
  • Different output channels use different filters.
  • ReLU adds nonlinearity. Pooling reduces spatial resolution.
  • The classifier maps the resulting features to class scores.

Track the shape after each layer. A change to convolution or pooling can change the required FC input size.
