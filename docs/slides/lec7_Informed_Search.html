Cost So Far and Estimated Cost Remaining

Informed search uses a heuristic: an estimate of the remaining cost to a goal.

  • g(n): cost of the current route from the start to n.
  • h(n): estimated cost from n to the goal.
Search Smallest priority first
Uniform-cost search (UCS) g(n)
Greedy best-first search h(n)
A* (“A-star”) f(n)=g(n)+h(n)

All three can use a min-priority queue. The priority key determines which entry comes out next.

Keep approximately 30-33 minutes for the slides and 17-20 minutes for the existing A* notebook. The two animated searches share one graph, so the second trace should move more quickly. Recall that UCS is uninformed even though it uses edge costs. A heuristic adds goal-directed information; it does not guarantee a speedup on every problem. Search terminology follows AIMA Chapter 3 and the archived Lecture 7.

Grid Distance as a Heuristic

Euclidean distance

h_{\text{Euc}}=\sqrt{(x_g-x)^2+(y_g-y)^2}

Here: \sqrt{4^2+3^2}=5.

Manhattan distance

h_{\text{Man}}=|x_g-x|+|y_g-y|

Here: 4+3=7.

With four-direction, unit-cost moves, 7 is the exact cost without walls. Walls can require extra moves.

The diagram uses Cartesian coordinates for the distance calculation. The notebook stores positions as (row, column), but the absolute-difference formula is identical. Diagonal moves are not allowed in this example. Both estimates are lower bounds under these movement rules, with Manhattan at least as informative as Euclidean. All distance diagrams are editable draw.io sources.

Designing a Heuristic

A relaxed problem removes a constraint. Its cheapest solution can provide a lower bound for the original problem.

Problem Simplification Heuristic
Four-direction unit grid Ignore walls Manhattan distance
Road routing by distance Allow a direct straight route Straight-line distance
8-puzzle, one slide costs 1 Let each numbered tile move independently Sum of tile Manhattan distances

For the 8-puzzle, the number of misplaced numbered tiles is another lower bound. Exclude the blank from both estimates.

The heuristic must match the allowed actions and the cost units. Kilometers cannot be added directly to minutes.

For the tile-distance heuristic, allowing tiles to move independently removes interference and the blank restriction. Every legal move changes the position of one numbered tile by one square, so the sum cannot exceed the number of moves required. With weighted grid moves, unscaled Manhattan distance is not automatically a valid cost estimate; a known minimum move cost can supply a scale factor. Relaxation and puzzle examples follow AIMA Chapter 3. See also https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html#141-heuristics.

Admissible Heuristics

An admissible heuristic never overestimates the cheapest remaining cost h^*(n).

0\le h(n)\le h^*(n).

At the goal, h(G)=0.

Node Estimate h True remaining cost h^*
S 2 4
A 2 2
B 1 8
C 1 1
G 0 0

The example’s heuristic is admissible, even though h(B)=1 is a poor estimate of 8. Admissible does not mean exact.

h-star is the optimal remaining cost, not the best cost from the start. All five inequalities can be checked on the displayed graph. Computing exact remaining costs generally requires solving the problem, which defeats the purpose of a cheap heuristic. Admissibility alone does not guarantee optimality for a graph-search implementation that permanently closes states without allowing improvements. The following slides distinguish those cases. Definitions follow the archived Lecture 7 and AIMA Chapter 3.

Goal Discovery Is Only a Proposal

After B, a route to G costs 9.

But A is still waiting with f(A)=4.

A frontier path on an optimal route has

f(n)\le C^*,

where C^* is the optimal solution cost.

For nonnegative costs and admissible h, preserve improved paths and test the goal on removal. A suboptimal goal cannot have the smallest f.

Assume nonnegative edge costs and a finite graph for the graph-search argument here. Preserve a best frontier prefix of an optimal route by allowing improved paths. On that prefix g is its optimal-route prefix cost, so g+h is at most C-star. A suboptimal goal has h=0 and f=g greater than C-star, so it cannot precede that prefix. This is not a claim that every arbitrary path to n has f at most C-star. For infinite or path-tree spaces, sufficient termination conditions include a reachable goal of finite cost, finite branching, a fixed positive lower bound on edge costs, and a nonnegative admissible heuristic. Proof reference: https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html#144-admissibility.

Consistency and Finalized States

A consistent heuristic obeys this inequality for every edge u\to v of cost c(u,v), with h(G)=0:

h(u)\le c(u,v)+h(v).

The estimated cost cannot drop by more than the cost of one move.

In our graph, A\to C satisfies 2\le 1+1. Therefore, along a path:

g(u)+h(u)\le g(u)+c(u,v)+h(v)=f(v).

With a consistent heuristic, the first current entry removed for a state has its optimal g. A finalized-on-removal set is safe.

Consistency implies admissibility for states with a route to a goal, by summing the edge inequalities to a goal with h=0. Nonnegative heuristic values and edge costs are the convention throughout. Manhattan distance on the notebook’s four-direction unit-cost grid is consistent because one move changes that distance by at most 1. The distinction matters when transferring UCS’s visited-on-pop implementation to A*. Reference: Poole and Mackworth, https://artint.info/3e/html/ArtInt3e.Ch3.S7.html, section 3.7.2.

A* Pseudocode: Select a Path

Each entry stores (f,g,u). best[u] records a path cost g, not a priority f.

best <- default_map(infinity); best[start] <- 0
parent[start] <- None; Q <- min_priority_queue()
push(Q, (h(start), 0, start))
while Q is not empty:
(priority, cost, u) <- pop_min(Q)
if cost != best[u]: # Skip an obsolete g value
continue
if u == goal:
return reconstruct(parent, goal), cost
RELAX_NEIGHBORS(u, cost)
return failure

For A: f=4, g=2, best[A]=2.

Compare g, not f, with best[A]; otherwise this valid entry would be discarded.

This is the best-g graph-search variant, not a transcription of the notebook. The queue compares the first field f; the stored second field g detects stale entries. The neighbor procedure on the next slide shares graph, h, best, parent, and Q with this loop. The heuristic is a fixed function of the state. A tie-breaking counter can be added for states without a natural ordering. Parent reconstruction is the same as Lecture 6. The goal test follows the stale-entry check.

A* Pseudocode: Improve a Route

For each edge u\to v with cost w, compare path costs, then compute the new priority.

RELAX_NEIGHBORS(u, cost)
for each outgoing edge (u, v) with cost w:
candidate <- cost + w
if candidate < best[v]:
best[v] <- candidate
parent[v] <- u
priority <- candidate + h(v)
push(Q, (priority, candidate, v))

At C: candidate = 3 + 1 = 4 < best[G] = 9.

Set parent[G] = C; insert (4,4,G).

Keep only strict improvements. Better routes can reopen a state.

The state space and its outgoing edges are available to the procedure. There is no permanent closed set, so an admissible inconsistent heuristic can trigger a reopening. As in Lecture 6, the push creates a new heap entry rather than changing the older one. The old G entry with g9 remains harmless. Distinguish this graph-search version from the notebook’s deliberately compact path-tree implementation.

Heuristic Quality and Memory

More informative estimates

  • h=0 gives UCS priorities.
  • If 0\le h_1\le h_2\le h^*, h_2 provides a tighter lower bound.
  • A stronger estimate may cost more to compute.

Limited memory

  • A* stores frontier entries and search records.
  • Simplified Memory-Bounded A* (SMA*) can forget a worst leaf and retain its backed-up estimate.
  • Forgotten branches may need to be generated again.

Search time depends on both the number of expansions and the cost per expansion. Saving memory can require repeated work.

This is a brief connection to the archived lecture’s memory-bounded search topic. A tighter admissible heuristic is more informative, but equal-f tie breaking and evaluation overhead mean elapsed time does not always improve. SMA* bounds stored search nodes, not merely an arbitrary truncated heap. It backs forgotten estimates up to parents and regenerates promising branches. Its completeness and optimality depend on having sufficient memory for the relevant solution path. Do not present dropping queue entries without bookkeeping as an optimal memory-bounded algorithm. Details follow AIMA Chapter 3 and the original Lecture 7.

What If the Heuristic Overestimates?

Change only h(A) from 2 to 10.

After S, which entry has smaller f?

After B, does A* choose A or G?

After S: f(B)=2, f(A)=12.

After B: f(G)=9, f(A)=12.

A* returns cost 9, missing the cost-4 route. Here h(A)=10>h^*(A)=2, so admissibility fails.

Pause for a prediction before revealing the arithmetic. The graph and edge costs have not changed. An overestimate does not force failure in every problem, but this counterexample shows that the optimality guarantee is lost. Even testing the goal on removal cannot repair an arbitrary overestimating heuristic.

Takeaways

  • Greedy ranks by h. A* ranks by g+h.
  • Admissibility bounds the remaining-cost estimate. Consistency permits finalizing states on removal.
  • Compare g costs when improving a route. Reopen states when necessary.
  • A heuristic guides exploration. Duplicate handling determines how much repeated work remains.
