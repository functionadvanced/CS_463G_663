Classifying vs. Generating

A discriminative model predicts a label for an existing image: “This is a seven.” A generative model learns what examples are plausible and how often they occur, so it can produce a sample: “Here is a handwritten seven.”

The counts show the data’s distribution: which patterns occur, and how often.

A sample is one random draw from the model’s learned distribution.

These constructed binary images and proportions carry over into Lecture 36. Only the three displayed patterns are possible in this toy distribution, not all sixteen two-by-two binary images. Repeating a pattern is expected in a small sample space. The contrast here is between the two tasks: a generative model can also be used for classification.

A Good Fit Preserves Variety

Both models can generate all three patterns. Which better matches the observed mix: 50% A, 30% B, 20% C?

Likelihood scores the fit to the whole dataset. M1 fits better: M2 favors A too strongly at the expense of the observed B and C images.

Choosing the most likely pattern always gives A. Sampling from M1 can also give B or C, though a small batch need not match the percentages exactly.

A common objective, negative log-likelihood (NLL), penalizes assigning low probability to observed examples. It scores all observations, including repeats, and will reappear for next-token prediction in Lecture 36. The bars are stipulated probabilities, not measured learning curves. Not all generative models give directly computable likelihoods.

Autoencoders and Latent Codes

An autoencoder learns to reconstruct its input. Its encoder compresses the image into a latent code (a hidden representation, shown as z). Its decoder turns the code back into an image.

Training measures reconstruction error: how different the decoded image is from the original.

Good reconstructions do not give us a sampling recipe. An arbitrary code can land where the decoder has had little training.

The compact code is schematic, not a learned representation of this pattern. A plain autoencoder can reconstruct deterministically. It might interpolate well between some codes, but the reconstruction objective alone does not identify a useful distribution to sample from.

Variational Autoencoders

A variational autoencoder (VAE) encodes each image as a distribution of possible codes. Training balances reconstructing the image with keeping those code distributions close to a prior, a chosen distribution such as a bell curve.

To generate, draw a code from the prior and decode it. There is no input image and no need to run the encoder.

Diederik P. Kingma and Max Welling (2013), Auto-Encoding Variational Bayes.

In the figure, x is the observed image, z is the latent code, and p(z) is the prior. The encoder predicts a distribution rather than a single code. Kullback-Leibler divergence is the usual prior-matching penalty. It encourages compatibility with the prior but does not guarantee that every prior draw gives a good image.

Generative Adversarial Networks

A generative adversarial network (GAN) trains two networks with competing goals:

  • The generator turns a random code (shown as z) into an image.
  • The discriminator learns to tell training images from generated ones. The generator learns to make that distinction harder.

To generate, pass a fresh random code to the trained generator.

Ian Goodfellow et al. (2014), Generative Adversarial Networks.

The discriminator is trained alongside the generator, not a fixed quality oracle. Adversarial here describes competing training goals. A basic GAN does not use an encoder to reconstruct each original image.

Diffusion: From Noise to an Image

A diffusion model learns to reverse gradual corruption. Denoising means estimating cleaner structure from a noisy input.

A noise schedule sets the corruption levels during training. At generation time, a sampler uses the trained denoiser to take steps from noisy to clean.

Start from fresh noise, not from a corrupted photo. The result is a plausible new sample, not a unique image that was hidden in the noise.

Jonathan Ho, Ajay Jain, and Pieter Abbeel (2020), Denoising Diffusion Probabilistic Models.

The path is schematic. With a suitable schedule the forward endpoint is close to Gaussian noise, a bell-shaped distribution. A sampler applies a series of updates using the denoiser’s prediction; those updates need not be simple subtraction and may also inject noise. A U-Net or Transformer can supply the denoising network.

Where the Denoiser Gets Its Targets

Start with a real image. Add known noise at a chosen level. Give the model the noisy image and its noise level (shown as x_t and t), without giving it the noise itself.

Train the predictor by comparing its guess with the noise we added. Repeat with different images and levels of corruption.

We can create the training targets ourselves by corrupting clean images. We do not need people to label the noise.

This is the noise-prediction design used in the DDPM example. The diagram uses squared error to compare the predicted and added noise. Other diffusion models can predict different targets. At generation time we do not have the clean image or the true noise target for each step.

Same Goal, Different Training Signals

Model What guides training? How do we get a new image?
VAE Reconstruct images and keep codes compatible with the prior. Draw a code from the prior and decode it.
GAN Improve the generator using feedback from a discriminator. Draw a random code and run the generator.
Diffusion Learn to denoise examples we deliberately corrupt. Start from noise and refine it over a series of steps.

In these examples, VAE and GAN generation use one decoder or generator pass. Diffusion uses multiple denoising passes.

Conditional Generation

Conditional generation gives the model extra information, called a condition, to guide what it produces.

Condition Possible output
Digit label: 7 A handwritten seven, with a particular stroke or slant
Text prompt: “a red bicycle” An image showing a red bicycle
Partial sentence: “The sky is …” A plausible continuation

For example, a conditional diffusion model can give the denoiser the prompt as well as the noisy image and noise level.

The same prompt can lead to different valid images. Conditioning guides the output; it does not guarantee that the model follows the request.

This is an input/output description, not a specific text-conditioning architecture. The condition can be supplied in a learned representation rather than as raw text. Lecture 36 studies generation by sampling one piece at a time.

Quality and Coverage

Quality asks whether individual samples look valid. Coverage asks whether the generator represents the variety of valid cases.

Mode collapse means generating too little of the data’s variety. In this example, every output is a valid A, but B and C never appear.

A gallery’s best image tells us little about coverage. Look at a batch of samples and count what is missing.

The figure shows a constructed failure, not measured GAN performance. Mode collapse is a common GAN concern, and poor coverage can affect other generators too. A diverse collection can still have low quality.

Evaluating a Generator

Held-out data was not used for training. Memorization means learning particular training examples in enough detail to potentially copy them.

Check What it reveals
Score held-out examples by negative log-likelihood (NLL), when available A lower loss means the model gives higher probability to the unseen examples overall
Compare outputs with the most similar training images Possible copies or repeated details
Inspect a batch of samples for quality, variety, and prompt following Artifacts, missing cases, or ignored conditions
Ask people to rate samples using clear criteria Whether people find the outputs useful or convincing

A sharp image can still copy a training example or ignore its prompt. No single check catches every failure.

Not all models give a tractable exact likelihood. An optional image metric is Frechet Inception Distance (FID), which compares feature statistics of real and generated images. See Heusel et al. (2017), https://arxiv.org/abs/1706.08500. Comparing outputs with training data is a diagnostic, not a guarantee of novelty or privacy.

Quick Check

  1. All generated digits look real, but every one is a seven. Which check exposes the problem?
  2. What do you run to generate from a trained VAE?
  3. Why do we know the right target when training a diffusion noise predictor?

1. Coverage. We cannot tell from one image that all other digits are missing.

2. The decoder. Give it a code sampled from the prior.

3. We added the noise. Its value is known during training.

Takeaways

  • A generator should capture a distribution, including less frequent examples.
  • A VAE samples and decodes a latent code. A GAN learns from a discriminator. Diffusion starts from noise and gradually denoises it.
  • A condition guides sampling without making every result identical.
  • Evaluate quality, coverage, prompt following, and memorization separately.
