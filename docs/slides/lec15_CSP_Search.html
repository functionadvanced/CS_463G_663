After Constraint Propagation

A constraint satisfaction problem (CSP) asks for values that satisfy every constraint. Propagation reduces domains, but may leave choices.

Remaining domains Next step
Any domain is empty Reject the current branch
Every domain is a singleton (one value) Verify the complete assignment against every constraint
Some domains have multiple values Choose a variable and try a value

Backtracking search tries a choice, continues recursively, and undoes the choice if the branch fails.

An empty domain after a tentative choice rules out that branch. Search can still try other choices.

Bridge from Lecture 14: AC-3 can return true without finding a solution. For node-consistent binary CSPs, if arc consistency has left every domain singleton, those values satisfy every binary constraint. The general solver should still validate all original constraints, especially when propagation handles only a subset. Start from a valid set of domains and fixed clues. Suggested pacing: worked search and basic pseudocode about 9 minutes, inference and restoration about 8, ordering and improved search about 10, advanced overview and notebook bridge about 6, leaving roughly 15 minutes for Sudoku. Sources: original Lecture 15 Beamer and AIMA’s CSP chapter.

A Three-Exam Search Problem

Exams A, B, C all share students, so every pair must use different slots.

D_A=D_B=\{1,2\},\qquad D_C=\{2,3\}.

If we try C=2, have we violated a constraint among assigned exams? No. A and B are still unassigned.

This is a separate three-exam example, with C allowed slots 2 and 3. Its two solutions, in (A,B,C) order, are (1,2,3) and (2,1,3). The initial domains are arc-consistent. C=2 is locally legal as a partial assignment but has no completion. We intentionally start with C and try 2 first to show how backtracking recovers. A different ordering can find the solution sooner.

A Backtracking Trace

Choose variables in the order C, A, B, trying smaller values first. The tree records choices; the triangle records constraints.

1. Try C=2.

2. A=1 leaves B no legal value. A=2 also conflicts with C.

3. Undo A and C, then try C=3.

4. A=1,\ B=2,\ C=3 satisfies every constraint.

No propagation is used in this first trace. At C=2, A=1 is the first legal value. B=1 violates A!=B, and B=2 violates B!=C. Return to A, undo A=1, and test A=2, which violates A!=C. A’s values are exhausted, so return to C, undo C=2, and try C=3. A=1 is legal; B=1 fails against A, while B=2 succeeds. A rejected candidate is never added to the assignment. The pink branch summarizes the failed checks; gold marks the current choice, and teal marks the successful path.

Assignment Order and Commutativity

Assigning A=1 then B=2 gives the same partial assignment as assigning them in the opposite order.

Let n count variables and d be the largest domain size. After k assignments, n-k variables remain.

  • Branching over variable-value pairs gives up to (n-k)d choices.
  • Selecting one variable first gives up to d value choices.

One variable per level avoids repeated assignment orders.

Commutativity concerns the resulting assignment for distinct variables, not an assertion that every ordering produces the same search effort or the same first solution. Before constraint pruning, an unconstrained n-variable problem with d values has d^n full assignments; considering every assignment order duplicates each one n! times. Standard CSP backtracking selects one variable at a node. A dynamic variable-selection rule is also valid. Source: supplied Lecture 15 Beamer and AIMA backtracking formulation.

Basic Backtracking

a is a consistent partial assignment, D stores domains, and C stores constraints. Start with a=\{\}.

BACKTRACK(a, D, C):
if a is complete: return COPY(a)
X ← SELECT_UNASSIGNED(a)
for v in D[X]:
if CONSISTENT(X, v, a, C):
a[X] ← v
result ← BACKTRACK(a, D, C)
if result != FAILURE: return result
REMOVE(a, X)
return FAILURE

CONSISTENT checks constraints whose variables have all received values. REMOVE undoes X’s tentative assignment.

This is depth-first search over partial assignments. Each recursive call removes its own failed choice before returning failure. Domains are unchanged in this basic version. The invariant is that the current assignment violates no fully instantiated constraint; thus a complete assignment is a solution. COPY protects the returned dictionary from later mutations. If every value for X fails, return to the caller’s choice. Source: original course algorithm and AIMA Figure 6.5, https://aima.cs.berkeley.edu/algorithms.pdf .

Search with Inference

After trying X=v, restrict D_X to \{v\}, then remove values ruled out by the constraints.

Check What it does after a choice
Check assigned values Reject an immediate conflict with earlier assignments
Forward checking Delete incompatible values from unassigned neighbors
Maintaining arc consistency (MAC) Propagate deletions through the remaining constraint graph

AC-3 (Arc Consistency Algorithm 3) can implement MAC by continuing to recheck affected arcs.

Forward checking looks one step from the new assignment. MAC also follows the effects of those deletions.

For a binary CSP, forward checking revises incoming arcs (Y,X) for unassigned neighbors Y of the chosen X, without propagating consequences between those neighbors. MAC restores arc consistency after each search choice. If the parent domains were already arc-consistent, AC-3 can start with incoming arcs to the newly restricted X. Otherwise initialize all directed arcs. Full propagation costs extra work per choice but may avoid much larger failed subtrees; neither method is universally faster. Sources: course search/inference material, AIMA CSP chapter, and Berkeley CS188 filtering notes.

Forward Checking and MAC

Return to the three exams. Every edge requires different slots. Try C=2.

Forward checking: D_A=D_B=\{1\}. Neither domain is empty yet.

MAC: revise (A,B). Value 1 has no unequal support, so D_A=\varnothing.

Propagation detects that the choice C=2 has no completion, before search assigns A and B.

At the first state, C is assigned but A and B remain unassigned. After basic forward checking they have forced values, but that method itself has not tested their mutual inequality. A solver may perform an additional check when assigning those singletons; MAC detects the conflict immediately by propagating between them. REVISE(A,B) leaves A empty while B remains {1}; stop on that first empty domain. This example explains a benefit of stronger propagation without claiming it always wins on runtime. The original domains are A12 B12 C23 and are arc-consistent before the choice.

Restoring a Failed Branch

The failed choice C=2 deleted values from several domains. Changing C alone does not repair the search state.

Restore the parent’s domains, then try C=3. The deletions belonged to the discarded branch.

Two common implementations: give each branch its own deep copy, or record deletions and undo them on return.

Restored domains are A={1,2}, B={1,2}, C={2,3}. Restoring to the parent means preserving earlier valid pruning, not blindly resetting to the original puzzle on every failure. Undo both assignments and domain changes when mutating shared state. A shallow dictionary copy that shares its sets does not isolate branches. The improved pseudocode uses branch-local deep copies, trading extra memory and copying work for simple state management.

Minimum Remaining Values

Minimum remaining values (MRV) selects the unassigned variable with the fewest current legal values.

A new four-exam example uses the edges shown below. All four exams are unassigned.

A, B, and D tie with 2 values. C has 3. Resolve a tie with another rule.

A singleton is forced. An empty domain signals failure. MRV often exposes difficult choices early.

Use current domains after filtering, not the size of the original unrestricted domains. A fixed order is still complete, but may postpone an important contradiction. MRV does not guarantee a smaller search tree on every instance. Here all four variables are unassigned and all pair constraints are inequalities. The domain sizes are A2, B2, C3, D2. Source: original variable-ordering material and https://inst.eecs.berkeley.edu/~cs188/textbook/csp/ordering.html .

The Degree Tie-Breaker

For an MRV tie, the degree heuristic prefers the variable constraining the most other unassigned variables.

Which of A, B, and D should be selected? A: degrees are A: 3, B: 2, D: 1.

Most constrained: fewest values. Most constraining: most unassigned neighbors.

The graph has AB, AC, AD, BC. All unassigned neighbor counts are A3, B2, C2, D1, but C is not in the MRV tie. Count constraints to unassigned variables in the remaining problem, rather than always using the original graph degree. Further ties can be broken deterministically. This is a standard heuristic, not a guarantee of the most effective choice for every instance. Source: original Lecture 15 and AIMA.

Least-Constraining Value

Least-constraining value (LCV) preserves the most neighbor options. In our three-exam problem, select C and compare forward-checking deletions.

C’s value New D_A New D_B Deletions
2 \{1\} \{1\} 2
3 \{1,2\} \{1,2\} 0

LCV tries C=3 first, avoiding the earlier failed branch.

This uses a one-step forward-checking score: add deletions across the unassigned neighbor domains. There are two deletions for C=2, one in A and one in B; there are none for C=3. More expensive LCV estimates may run fuller inference per candidate. Such simulations need copies or correct restoration as well. LCV changes value order; it does not discard the other values if the first attempt fails. It is particularly useful when seeking one solution. Source: original Lecture 15 and Berkeley CS188 ordering notes.

Backtracking with Heuristics and AC-3

For a binary CSP, SOLVE uses domains as its state. CHECK_SOLUTION verifies every constraint and returns the assignment or FAILURE.

SOLVE(D, C):
if any D[X] is empty: return FAILURE
if all domains are singleton: return CHECK_SOLUTION(D,C)
X ← MRV_WITH_DEGREE(D, C)
for v in LCV_ORDER(X, D, C):
child ← DEEP_COPY(D)
child[X] ← {v}
if AC3(child, C):
result ← SOLVE(child, C)
if result != FAILURE: return result
return FAILURE

Each branch gets its own domains. If it fails, discard that copy and try the next value using the intact parent state.

MRV_WITH_DEGREE selects a variable with more than one remaining value, since singleton variables are already fixed in this domain-based representation. Start with unary constraints enforced. AC3 checks all directed arcs in this version, so it need not assume the input state is already arc-consistent. Inference returning true permits recursion but does not establish success. Every branch strictly fixes a previously nonsingleton variable, so the finite search terminates and is complete if all domain values are tried when necessary. Unlike the basic algorithm, explicit assignment undo is unnecessary because state is isolated in child. The notebook implements this copied-domain search pattern with singleton propagation and MRV, rather than full AC-3, degree tie-breaking, or LCV. Source: original improved search pseudocode and AIMA Figure 6.5, adapted to make branch restoration explicit.

Backjumping and Constraint Learning

A separate example assigns A=1,\ B=2,\ T=1, in that order. D_X=\{1,2\}, with rules X\ne A and X\ne B. T is unrelated.

  • Conflict set: earlier choices that explain a failure. Here it is \{A=1,B=2\}.
  • Backjumping: revisit the most recent decision in that set, so change B before trying an unrelated T value.
  • Constraint learning: remember a no-good, a partial assignment that cannot lead to a solution. Here, forbid the combination A=1,\ B=2.

X=1 conflicts with A=1 and X=2 conflicts with B=2. The original domain of X is exactly {1,2}, so neither value works and the two decisions jointly explain failure. T was assigned more recently than B but contributes nothing. Jump to B, undoing later choices, including T. Conflict-directed backjumping also combines reasons from deeper failed subtrees. Basic backjumping’s immediate dead ends are already caught by forward checking, while more elaborate learning can retain explanations for future search. This is an introductory overview. Source: AIMA’s freely available CSP chapter, https://aima.cs.berkeley.edu/newchap05.pdf , section on intelligent backtracking.

Complete Search and Local Repair

A CSP can also be approached through the local-search methods from Lecture 11.

Method Search state How it handles conflicts
Backtracking A partial assignment Reject choices and return to earlier decisions
Min-conflicts A complete assignment that may violate constraints Change a conflicted variable to a value with fewer conflicts

Min-conflicts can solve large instances quickly, but may get stuck or need restarts.

For finite domains, exhaustive backtracking can prove that no solution exists. A failed local-search run generally cannot.

A min-conflicts step typically selects a conflicted variable, evaluates the number of constraint violations for its possible values, and chooses a minimum-conflict value with randomized tie handling as appropriate. Unlike backtracking, the current full assignment may be invalid. This reconnects the CSP formulation to local repair without introducing another code demo. Source: original Lecture 15 Other Improvements and AIMA min-conflicts search.

Each blank is a variable. Row, column, and 3\times3 box constraints forbid repeated digits.

  • solve: choose the first blank, recurse, and reset it to zero after failure.

Takeaways

  • Backtracking tries choices and returns when a branch fails.
  • Forward checking and MAC prune after each choice.
  • MRV chooses a variable with few remaining values.
  • The degree heuristic breaks ties using remaining neighbors.
  • LCV tries values that preserve more options.
  • Every failed branch must restore its assignments and domains.

A reliable solver combines correct state management with good branching choices and useful propagation.
