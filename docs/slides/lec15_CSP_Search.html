CSP Search

  • Constraint propagation can reduce domains.
  • Sometimes propagation alone solves the problem.
  • Sometimes it proves failure.
  • Often it only makes the remaining search easier.

CSP solvers usually combine propagation with backtracking search.

After Propagation

Domain state Meaning
Every variable has one value Problem solved
Some variable has no values Current path fails
Some domains are smaller Search is easier, but not done

When propagation stops, what should the solver try next?

Backtracking Search

  • Choose an unassigned variable.
  • Try a value from its domain.
  • Continue recursively.
  • Undo the choice if it leads to failure.

Commutativity

In CSPs, the final assignment does not depend on the order in which variables were assigned.

Naive View

If there are x variables and each has y values, a naive action choice has branching factor xy.

CSP View

Choose one variable first; then branch only over its values. Branching factor becomes y.

Commutativity lets us search assignments, not action permutations.

Basic Backtracking

Backtrack(assignment):
if assignment is complete:
return assignment
 
X = select an unassigned variable
 
for each v in Domain(X):
if assigning X = v is consistent:
add X = v to assignment
result = Backtrack(assignment)
if result is not failure:
return result
remove X = v from assignment
 
return failure

Improving CSP Search

Because CSPs share common structure, we can improve search in domain-independent ways.

Improvement Question
Inference What values can be pruned after a choice?
Variable ordering Which variable should be assigned next?
Value ordering Which value should be tried first?
Backjumping / learning What caused failure, and can we avoid repeating it?

Search and Inference

Search

Assign values to variables and backtrack when constraints fail.

Inference

Reduce domains by enforcing consistency before making more assignments.

Two options after assigning variable v:

  • Check only constraints involving v.
  • Run fuller propagation starting from constraints involving v.

Inference Tradeoff

Method Cost Benefit
Local consistency around v Faster May miss useful implications
Fuller propagation Slower Prunes more and often pays off

Large CSPs often need strong branching-factor reductions, so fuller propagation is frequently worth the extra cost.

Variable Ordering

MRV

Choose the variable with the fewest remaining values.

This tends to fail fast.

Most-Constraining Variable

Choose the variable involved in the most constraints.

This is useful for tie-breaking.

Value Ordering

Least-Constraining Value (LCV)

  • Try the value that removes the fewest options from other variables.
  • This keeps future choices flexible.
  • It helps when we only need one feasible value for the current variable.

Variable ordering chooses where to branch; value ordering chooses how to branch.

Improved Backtracking

ImprovedBacktrack(assignment):
if assignment is complete:
return assignment
 
X = most-constrained unassigned variable # MRV
order values for X by least-constraining value # LCV
 
for each v in D(X):
if v is consistent with assignment:
assign X = v
perform inference, such as AC3
if inference did not detect failure:
result = ImprovedBacktrack(assignment)
if result is not failure:
return result
undo assignment and restore domains
 
return failure

Backjumping

  • Standard backtracking returns to the most recent choice.
  • Backjumping returns to the earliest decision that actually caused failure.
  • Simple backjumping often overlaps with what constraint propagation would prune.

Backjumping asks: “Which previous choice made this failure inevitable?”

Other Improvements

  • Conflict-directed backjumping: jump using the exact cause of failure.
  • Constraint learning: store no-good combinations so they are not repeated.
  • Local search for CSPs: useful when complete backtracking is too expensive.
