Context Changes a Word’s Meaning

A Transformer is a neural-network architecture that uses attention to combine information from different sequence positions, without recurrent state updates.

Attention produces a contextual representation: a numeric vector influenced by the surrounding input, not only by the word itself.

Introduced by Ashish Vaswani et al. (2017), Attention Is All You Need.

The river/money connections illustrate possible contextual relationships; they are not observations from a trained model, nor a claim that a single attention weight explains a prediction. A real tokenizer can split words into subword pieces. This lecture develops the supplied Beamer attention material using column vectors, consistent with Lecture 38. The full Transformer also includes feedforward layers, residual connections, normalization, and positional information; it is not just one attention operation. The original paper contains an encoder-decoder architecture, while other Transformers can be encoder-only or decoder-only.

From Recurrence to Attention

A recurrent neural network (RNN) passes a hidden state through positions one by one. Attention compares a position directly with other available positions; known positions can be processed together.

For an autoregressive Transformer, generation still chooses one new token at a time. The prefix is the sequence chosen so far.

Attention returns feature vectors. An output head maps the final representations to next-token scores; softmax normalizes those scores into probabilities.

The diagram summarizes a decoder-only language model, not every Transformer. The output head is the final prediction mapping, followed by softmax over the vocabulary. The attention weights discussed later instead normalize over context positions. A feedforward computation across layers is still sequential in depth; parallel positions do not mean all computation happens at once. A conventional autoregressive decoder must wait for the actual previous sampled token. Caching does not remove that dependency.

Tokens Become Embedding Vectors

A token is a text piece, such as a word or subword. An embedding maps its integer ID to a learned vector by looking up a column of a matrix E.

For n positions and embedding dimension d_e, we place one vector x_i in each column:

X=[x_1\ \cdots\ x_n]\in\mathbb R^{d_e\times n},\qquad X=\begin{bmatrix}1&1&1\\1&0&1\end{bmatrix}\text{ in this example}.

The repeated ID has the same lookup vector. Position information and later attention distinguish its occurrences.

The table uses zero-based IDs and invented two-dimensional embeddings, not learned word meanings. Here n=3 and d_e=2. Embeddings are parameters trained by gradient descent, not usually one-hot vectors. Positional information is separate from the token lookup; Lecture 38 develops it. Keep column-vector layouts throughout this lecture, even though many library interfaces use sequence positions as rows.

Query, Key, and Value

Think of retrieving information from a station noticeboard:

  • A query describes what the current position seeks.
  • A key describes what a stored position can match.
  • A value carries the content to combine into the answer.

In neural attention, all three are vectors. Query-key matches set weights; those weights mix the values rather than copying one database record.

The noticeboard is an analogy for the three roles, not an actual vector calculation or a fixed symbolic lookup algorithm. Keys and values are paired by context position. The learned projections on the next slide need not encode human-readable labels. The numeric example later uses constructed vectors, unrelated to real train times or text embeddings.

Learned Projections Create Q, K, and V

Let X\in\mathbb R^{d_e\times n} contain the context vectors to read, and X_Q\in\mathbb R^{d_e\times m} the vectors making m queries. A linear projection multiplies vectors by a learned matrix.

K=W_KX,\qquad Q=W_QX_Q,\qquad V=W_VX.

Keys and queries have d_k features so they can be compared. Values have d_v features; d_v need not equal d_k.

Q, K, and V stand for query, key, and value. The matrices W_K and W_Q each have shape d_k by d_e, and W_V has shape d_v by d_e. This simple presentation uses the same input feature dimension for context and query sources. Biases are omitted. Projected vectors, not token IDs, enter the attention computation. The matrices are trained jointly with the model; they do not change during a single generation run.

One Query, Three Key-Value Pairs

Use already-projected, invented vectors: n=3, d_k=d_v=2, and one query q=(1,0)^T.

Placing the pairs in corresponding columns gives

K=\begin{bmatrix}1&0&1\\0&1&1\end{bmatrix},\qquad V=\begin{bmatrix}2&0&2\\0&2&2\end{bmatrix}.

We will compare keys, normalize scores, then mix values.

The coordinates have no assigned linguistic meaning. The vectors are chosen so the dot products and weighted sum are easy to verify. Column j of K and column j of V describe the same context position. These are outputs of projections, so W matrices are not needed to run this calculation.

Step 1: Compute Matching Scores

The dot product k_i^Tq compares key k_i with query q=(1,0)^T. Divide by \sqrt{d_k}=\sqrt2 to get a scaled score s_i.

s=\frac{K^Tq}{\sqrt{d_k}}= \begin{bmatrix}1/\sqrt2\\0\\1/\sqrt2\end{bmatrix} \approx\begin{bmatrix}0.707\\0\\0.707\end{bmatrix}.

Why scale? Dot products tend to grow with the number of features. Scaling helps keep the next normalization from becoming excessively sharp.

This matching score is not cosine similarity: vectors are not normalized to unit length. For independent zero-mean unit-variance query and key components, the dot product has variance d_k; division by sqrt(d_k) gives unit variance. This is intuition for the scaling, not an exact law for learned vectors. Values do not enter the matching score. References: Vaswani et al., Section 3.2.1 and its variance footnote.

Step 2: Turn Scores into Weights

Softmax converts the n scores into nonnegative weights \alpha_i that sum to 1:

\alpha_i=\frac{e^{s_i}}{\sum_{j=1}^n e^{s_j}}.

For s=(1/\sqrt2,0,1/\sqrt2)^T, the common denominator is approximately 2.028+1+2.028=5.056.

Does the zero score at position 2 mean zero attention weight?

No. e^0=1, so position 2 still gets about 0.198 of the weight.

For finite unmasked scores, softmax weights are strictly positive. Masking a position with negative infinity makes its weight zero; masks come later. The exact symmetric weights are computed before rounding the displayed values. Stable softmax subtracts the maximum score before exponentiation; that common shift leaves the result unchanged. The distribution here is over context positions, not next-token vocabulary entries.

Step 3: Mix the Values

The output vector o is the weighted sum of the paired values:

\begin{aligned} o=V\alpha &\approx0.401\begin{bmatrix}2\\0\end{bmatrix} +0.198\begin{bmatrix}0\\2\end{bmatrix} +0.401\begin{bmatrix}2\\2\end{bmatrix}\\[0.3em] &\approx\begin{bmatrix}1.604\\1.198\end{bmatrix}. \end{aligned}

The result blends content from several positions. It is a feature vector, not a selected token ID or a next-token probability distribution.

The first coordinate is 2 times (alpha_1+alpha_3), and the second is 2 times (alpha_2+alpha_3). Three-decimal output rounding agrees with the unrounded calculation. Attention averages values, not keys. Since the weights are nonnegative and sum to one, this single attention output lies in the convex hull of its value vectors; later projections and residual updates need not have that restriction relative to these values.

Practice: Change Only the Query

Keep the keys and values, but use q'=(0,1)^T:

K=\begin{bmatrix}1&0&1\\0&1&1\end{bmatrix},\qquad V=\begin{bmatrix}2&0&2\\0&2&2\end{bmatrix},\qquad d_k=2.

Which positions now match equally well? Compute the scaled scores, weights, and output. You may use e^{1/\sqrt2}\approx2.028.

s'\approx(0,0.707,0.707)^T, so positions 2 and 3 tie.

\alpha'\approx(0.198,0.401,0.401)^T and o'\approx(1.198,1.604)^T.

For q=0, all scores are zero: \alpha=(1/3,1/3,1/3)^T and o=(4/3,4/3)^T.

Pause before revealing the first answer. The first output was approximately (1.604,1.198)^T; changing only the query swaps the two coordinates here because of the deliberately symmetric example. Ask about the zero-query case before revealing the second answer. A zero query gives uniform weights only over allowed positions; this example has no mask.

Many Queries in One Matrix Operation

Let Q=[q_1\ \cdots\ q_m]. Each query gets a column of attention weights in A and a column of outputs in O:

A=\operatorname{softmax}_{\text{columns}}\!\left(\frac{K^TQ}{\sqrt{d_k}}\right), \qquad O=VA.

K:d_k\times n, Q:d_k\times m, V:d_v\times n. Thus A:n\times m and O:d_v\times m.

Normalize down each column, over keys for one query. Do not normalize across different queries.

The diagram uses the two previous queries q and q’ as columns of Q. Its rows index context positions, and its columns index queries. Multiplication by V independently mixes the same value bank for each query. In the toy case O has columns (1.604,1.198)^T and (1.198,1.604)^T. Many implementations orient the matrices differently; the later row-layout slide makes that transpose explicit.

Attention Computation

Inputs are already projected. @ means matrix multiplication, and Rows(K) counts key features.

function Attention(Q, K, V)
dk = Rows(K)
scores = (Transpose(K) @ Q) / sqrt(dk)
weights = Softmax(scores, axis=0)
return V @ weights

For this two-dimensional score matrix, axis 0 runs down rows: over keys, separately for each query column.

Queries and keys determine weights. Values determine the content combined using those weights.

This is pseudocode, not a notebook or a batched PyTorch implementation. It omits dropout and masking. Show the dimensional scaling, score computation, normalization, and value mixture in sequence. Softmax should use a numerically stable implementation, not naive exponentiation of large scores. Use matrix multiplication rather than elementwise multiplication. The function expects matching query/key dimensions and equal key/value position counts.

Check the Matrix Shapes

There are n=10 context positions and m=4 queries. Embeddings have d_e=64 features; keys/queries have d_k=16 and values have d_v=32.

What are the shapes of K,Q,V, of the score/weight matrix, and of the output? Keep one vector per column.

K:16\times10, Q:16\times4, V:32\times10.

K^TQ:(10\times16)(16\times4)=10\times4. Softmax keeps this shape.

O=VA:(32\times10)(10\times4)=32\times4: one output per query.

The embedding dimension determines the projection input dimensions, not the output vector count. As a follow-up, W_K and W_Q have shape 16 by 64, and W_V has shape 32 by 64. Four queries do not mean four stored values; each of the four outputs mixes the same ten values with its own weights.

Self-Attention and Cross-Attention

Self-attention draws queries, keys, and values from the same sequence. Cross-attention uses queries from one sequence and keys/values from another.

In translation, an encoder represents the input sentence; a decoder builds the output sentence using the earlier output tokens and the encoded input.

Self-attention means X_Q=X, not Q=K=V. Separate learned projections can produce different vectors from the same input.

The figure illustrates source French Le train part and English prefix The train, not a trained alignment. A decoder normally contains causal self-attention as well as cross-attention in an encoder-decoder model. Decoder-only language models do not require this source-to-target cross-attention module. Neither different projection names nor common input imply that all projected values must be pairwise unequal; they can coincide in special cases.

Parallel Training, Sequential Generation

During training, the full observed sentence is available. Teacher forcing uses its correct earlier tokens to predict each next token.

A causal mask blocks attention to later input positions, so a next-token prediction cannot read its own target or later tokens.

Many training positions can run in parallel. Ordinary autoregressive generation still extends the actual prefix one token at a time.

The target is shifted one position after its corresponding input. The representation after input position j may use positions up to j and predicts token j+1. Masking must apply at every attention layer, not just at the output. The next lecture develops the mask and full blocks. Parallel attention does not bypass dependencies between layers or between sampled future tokens. An RNN still has a recurrence dependency between training positions even when all inputs are known.

Dense Attention Has Quadratic Cost

Dense self-attention compares every position with every position, giving n^2 query-key scores for a sequence of length n.

At n=1{,}000, there are 1 million scores; at n=2{,}000, there are 4 million.

Why does doubling the sequence length quadruple the number of scores?

There are twice as many queries and twice as many keys: (2n)^2=4n^2.

These counts describe one attention head before masking. A head is one attention computation; multiple heads are developed next lecture. Causal masking reduces the allowed pairs but does not remove quadratic scaling for dense computation. Arithmetic for scores and value mixing is O(n^2 d_k+n^2 d_v), excluding projections. Optimized attention kernels can avoid storing the full score matrix, so this is not a claim that every implementation allocates n^2 entries simultaneously. Sparse or other attention variants need not use every pair.

Reading the Row-Vector Formula

Today, positions are columns and softmax normalizes down each column:

O=V\,\operatorname{softmax}_{\text{columns}}\!\left(\frac{K^TQ}{\sqrt{d_k}}\right).

The original paper and common library layouts use rows. Define Q_r=Q^T, K_r=K^T, V_r=V^T, and O_r=O^T:

O_r=\operatorname{softmax}_{\text{rows}}\!\left(\frac{Q_rK_r^T}{\sqrt{d_k}}\right)V_r.

Here Q_r:m\times d_k, K_r:n\times d_k, and V_r:n\times d_v. Normalize across each row, over its n keys.

Same calculation, different storage layout. Do not mix one convention’s formula with the other’s normalization axis.

Library reference: PyTorch scaled dot-product attention.

The transpose of a column-wise softmax is a row-wise softmax of the transposed score matrix. The library function also supports leading batch/head dimensions and optional masks/dropout, omitted here. In its row layout the softmax dimension is the last score dimension. Lecture 38 continues with the column-vector convention, so this slide is a translation guide, not a notation switch.

Quick Check

1. If only V changes, do the attention weights change?

No, if Q and K stay fixed. The weights stay the same, although the output may change.

2. Does self-attention force Q and K to be identical?

No. They come from the same sequence but use separate learned projections.

3. Are attention weights probabilities over the vocabulary?

No. They mix context positions. A language model’s output head predicts vocabulary probabilities.

Takeaways

  • Embeddings represent tokens; attention makes representations depend on context.
  • Queries and keys determine weights; values supply the mixed content.
  • With column vectors, normalize over keys down each score column.
  • Parallel training is compatible with sequential generation.
