Representation Comes Before Search

In artificial intelligence (AI), search is one way to choose actions by considering possible futures.

  1. Represent: What situations and actions matter?
  2. Search: Which action sequence reaches a goal?
  3. Execute: Carry out the selected actions.

An algorithm cannot fix a problem that was modeled incorrectly.

The slogan representation plus search describes a major classical AI approach, not every AI system. Distinguish searching in a model from physically trying every road. Search spends computation to avoid unnecessary real-world actions.

What Are We Assuming?

Recall the environment dimensions from Lecture 3.

Assumption here What it lets us do
Fully observable Know the current state
Known, deterministic actions Predict one next state for each action
Static during planning Plan before executing the first action
Single agent Ignore an opponent’s choices

Under these assumptions, a solution can be a fixed sequence of actions.

These are the assumptions of the introductory search formulation, not requirements for every use of search. With uncertainty, a fixed sequence may be insufficient: the agent may need a policy that reacts to observations. A real navigation application can replan when traffic changes. That is outside today’s static example.

Define the Search Problem

Component Question to answer
Initial state Where does the agent start?
Available actions Which choices are legal in each state?
Transition model What state results from an action?
Goal test Does this state satisfy the objective?
Action cost What does each action cost?

The state space contains the possible modeled states. The path cost is the sum of action costs along a path.

Some textbook lists treat action cost and path cost together. Here action costs define an additive path cost. Costs can represent time, distance, money, or a unit cost per move; they should match the intended objective. State space may include valid states that are not reachable from a particular start.

Turn the Map into a Problem

Component Our navigation task
State / initial state Current location / S
Actions / transition Take a neighboring road / arrive at its other end
Goal test Is the current location G?
Action cost Minutes written beside that road

At S there are two actions: go to A or go to B. At B there are three: go to S, C, or G. Road direction matters; this example explicitly uses bidirectional roads. The graph is small enough to draw, but a real search implementation can generate neighbors as needed.

Shortest in Steps or Cheapest?

Route Number of actions Total travel time
S → B → G 2 2+6=8 minutes
S → A → C → G 3 1+1+1=3 minutes

With equal positive action costs, a route with the fewest actions is also a least-cost route.

The three-minute route is optimal in this map: S to A to C to G has three unit-cost edges; the other simple routes cost at least four. Students do not need an optimality proof yet. This example motivates the difference between breadth-first and uniform-cost search later.

What Must a State Remember?

A search state is a task-relevant summary, not a copy of the whole world.

  • Plain road planning: current location may be enough.
  • A locked door: location and whether you have the key.
  • Limited battery: location and remaining charge.

Keep information that changes legal actions, outcomes, goal status, or future costs.

Two histories can be merged into one state when they have the same relevant future possibilities. The path already traveled can stay in a search node; it need not be part of the problem state unless history changes the future task. For example, if roads are time-dependent, current time may also matter.

Pair Exercise: Pick Up a Package

A robot starts at Home, visits the Shop to pick up one package, and returns Home with it.

  1. Is current location alone a sufficient state?
  2. What is the initial state? What is the goal test?
  3. Specify the pickup action and its cost.

The robot starts at Home. Is the task already done?

Let pairs propose a state representation. Specify that the shop always has the package, pickup succeeds, the robot cannot drop the package, and each road is bidirectional. The next slide chooses a unit cost for pickup as well as travel. Students could instead choose a different explicit pickup cost without changing the need for a package flag.

A State Includes Package Status

\text{state}=(\text{location},\ \text{has package})

Piece Definition
Initial state (\text{Home},\ \text{false})
Pickup action At Shop without package: change the flag to \text{true}
Goal test Location is Home and package flag is \text{true}
Costs in this model Each road traversal and pickup costs 1

A solution: Home → Junction → Shop → pick up → Junction → Home. Cost: 5.

There are three locations times two package-status values, or six possible states. All six are reachable in this model. Home without the package and Home with the package are different states even though the robot occupies the same physical location. Show why the initial state fails the correct goal test.

Vacuum World: Count the States

  • Vacuum location: A or B.
  • Room A: clean or dirty.
  • Room B: clean or dirty.

2\times 2\times 2=8\text{ states}

We will write a state as (\text{location},\ \text{A status},\ \text{B status}).

How many states satisfy “both rooms are clean”?

Two. The vacuum may finish in either room.

Both cleanliness values are known. No new dirt appears and cleaning always succeeds. The eight states describe the whole modeled state space; from a specific start with one clean room, some of these states cannot be reached because actions do not create dirt. The illustration is from Artificial Intelligence: A Modern Approach by Stuart Russell and Peter Norvig.

Vacuum Actions: L, R, and S

Label Full action name Effect in this two-room model
L Move Left End in A; stay put if already in A
R Move Right End in B; stay put if already in B
S Suck up dirt Make the current room clean
  • Each action costs 1, even if nothing changes.
  • Cleaning an already-clean room leaves the state unchanged.
  • Goal: both rooms clean, regardless of vacuum location.

Specify actions with no effect too. Otherwise, two implementations may model different problems.

The labels on the next diagram are action abbreviations, not state names. Contrast S here, which means Suck, with S on the earlier road map, which labels the start location. The meanings are local to each example.

Work Through a Vacuum Plan

Initial state: (\text{A},\ \text{dirty},\ \text{dirty}).

Step Action Resulting state Cost so far
0 Start (\text{A},\ \text{dirty},\ \text{dirty}) 0
1 Suck (S) (\text{A},\ \text{clean},\ \text{dirty}) 1
2 Right (R) (\text{B},\ \text{clean},\ \text{dirty}) 2
3 Suck (S) (\text{B},\ \text{clean},\ \text{clean}) 3

Could any solution cost less than 3 from this start?

No. Each dirty room needs a cleaning action, and reaching the other room needs at least one move.

Trace each action before discussing optimality. This is a lower-bound argument: every valid solution needs two cleanings and one move, and this plan achieves that bound. An alternative sequence Right, Suck, Left, Suck is valid but costs four. Reinforce valid versus optimal.

The 8-Puzzle: Start and Goal

Slide a numbered tile into the empty square. Reach the specified target arrangement.

What is one action? Does “move left” describe a tile or the blank?

Use the AIMA figure’s actual goal, which has the blank at the top left. Other puzzle versions use a different goal; the problem definition must state which one. The ambiguity about move direction is intentional and resolved on the next slide. Source: Artificial Intelligence: A Modern Approach, Figure 3.3.

Make Puzzle Actions Unambiguous

Component Our 8-puzzle definition
State Positions of all eight tiles and the blank
Actions Move the blank up, down, left, or right when legal
Transition Swap the blank with the adjacent tile in that direction
Goal test Does the whole board match the target?
Action cost 1 per swap

How many legal actions are available with the blank in the center? In a corner?

Four in the center; two in a corner. The action set depends on the state.

In the displayed start, moving the blank left swaps it with tile 5, so tile 5 moves right. The branching factor is not constant across states. Not every arrangement is reachable from a fixed start; parity divides the configurations into two equally sized reachable components. Mention only if asked, since reachability parity is not needed for this introductory formulation.

Eight Queens: A Different Kind of Goal

  • Place 8 queens on an 8\times 8 board.
  • No two queens share a row, column, or diagonal.
  • We care about a valid final arrangement, not travel distance.

Should an action place a queen anywhere, or only in a carefully chosen column?

Explain a queen’s attack directions for students unfamiliar with chess. Contrast navigation, where we need the path, with a configuration task, where the final assignment is the main result. Incremental placement gives a search formulation; later constraint-satisfaction and local-search lectures revisit this problem.

A Better Representation Removes Work

Place queens one column at a time, from left to right.

Choice Candidate complete boards before attack checks
Any 8 distinct squares \binom{64}{8}=4{,}426{,}165{,}368
Exactly one queen per column 8^8=16{,}777{,}216

The second representation rules out column conflicts automatically.

These counts are candidate boards, not valid solutions or the number of nodes an algorithm must visit.

The counts compare completed placements only. The first representation chooses an unordered set of eight squares; counting placement orders instead would count many paths to the same board. This distinction corrects the approximate state counts in the old lecture. Since every valid solution already has exactly one queen per column, imposing that structure does not remove any solution.

Reject Impossible Partial Solutions

Suppose column 1 already has a queen in row 1. Where can the next queen go in column 2?

Pruning means discarding a branch that cannot lead to a valid solution.

With placement-only actions, adding more queens cannot repair an existing attack.

Column 1 row 1 attacks column 2 rows 1 and 2. Rows 3 through 8 are legal immediate placements, but not all necessarily extend to complete solutions. Ask why this pruning is safe for incremental placement but would not justify rejecting an entire full-board local-search state where moving an existing queen is allowed.

Same State, Different Search Nodes

A state describes a situation. A search node also records how we reached it.

A node n can store its state, parent node, last action, depth (actions so far), and path cost g(n).

Two nodes can describe the same state but have different paths and costs.

The drawing shows selected branches of the search tree, not the full tree. The underlying road graph has one vertex C. The path through A reaches C at cost 2; through B reaches C at cost 3. Both nodes have depth 2. In g(n), n denotes a search node, not the number of nodes. Parent links let us reconstruct the action sequence without copying the whole path into every child.

The Frontier: Discovered, Not Expanded

  • Expand a node: generate children using its available actions.
  • Frontier: nodes still waiting to be explored.
  • Reached states: states already discovered, including those on the frontier.

Which frontier node should we choose next? That choice defines the search strategy.

Distinguish generated from expanded. S is removed from the frontier and expanded. A and B have been generated but not expanded. Reached is a set of problem states, whereas the frontier stores search nodes. Cost-aware search may instead record the best known cost for each reached state and update it when a cheaper route is found.

A Common Search Skeleton

Python-style pseudocode for finding a reachable goal; helper operations are conceptual.

frontier = [Node(initial_state)]
reached = {initial_state}
while frontier:
    node = choose_and_remove(frontier)
    if is_goal(node.state):
        return reconstruct_path(node)
    for action in actions(node.state):
        child = make_child(node, action)
        if child.state not in reached:
            reached.add(child.state)
            frontier.append(child)
return failure

The selection rule changes exploration order. Finding the cheapest path also needs careful handling of better routes to known states.

Step through the highlighted groups. Node creates a root; choose_and_remove applies a selection rule; make_child uses the transition model and stores parent, action, depth, and cumulative cost; reconstruct_path follows parents backward then reverses the actions. failure is a conceptual result meaning no reachable goal was found. The snippet belongs inside a search procedure and is not a standalone executable Python program.

This version marks states reached when generated and discards later duplicates. For a finite state space, it finds a reachable goal, but does not in general find the least-cost path. It can safely remove cycles for reachability because all future possibilities are represented by the state. Uniform-cost and A* search need best-cost tracking and appropriate updates. Do not present this as their implementation.

Your Turn: Expand One More Node

After expanding S: frontier = [A, B], reached = {S, A, B}.

Now choose A, using the search skeleton from the previous slide.

  1. Which neighbors does A generate?
  2. Which one is already reached?
  3. What remains on the frontier? What is the new node’s cost?

Allow roughly 90 seconds. The frontier lists locations for readability, but its entries are search nodes. S to A costs 1. A has neighbors S and C. We choose A explicitly rather than introducing a queue or stack policy yet.

Trace: Skip S, Add C

Operation Frontier Reached states
Before selecting A [A, B] {S, A, B}
Remove A [B] {S, A, B}
Generate S; already reached [B] {S, A, B}
Generate C; add it [B, C] {S, A, B, C}

The C node has parent A, depth 2, and cost g(C)=1+1=2.

Without a repeated-state check, a two-way road can create paths such as S → A → S → A → … forever.

g(C) is shorthand here for the cost of the C search node reached through A. Emphasize that A remains in reached after leaving the frontier. The search order determines whether an algorithm actually gets trapped by repeated paths, but the search tree contains arbitrarily long repeated walks unless we eliminate them.

Three Uninformed Search Strategies

Uninformed means no estimate of the remaining distance to the goal. The problem’s action costs may still be used.

Abbreviation Full name Which node is selected next?
BFS Breadth-First Search Shallowest: fewest actions so far
DFS Depth-First Search Deepest along the current branch
UCS Uniform-Cost Search Smallest accumulated path cost

Which strategy directly matches our objective of minimizing travel time?

UCS. It prioritizes cost, not the number of roads traveled.

Preview only: breadth-first typically uses a first-in, first-out queue; depth-first uses a last-in, first-out stack or recursion; uniform-cost uses a priority queue. Avoid introducing the queue abbreviations before students see those data structures next lecture. Explain that UCS selects the smallest cost so far, not a guaranteed smallest remaining cost. Its optimality depends on the correct goal test and cost-aware duplicate handling.

Depth Limits and Repeated Searches

Abbreviation Full name Idea
DLS Depth-Limited Search Depth-first search with a maximum number of actions
IDS Iterative Deepening Search Repeat depth-limited search with limits 0, 1, 2, …

If the shallowest goal needs 3 actions:

\text{limit }0\ \longrightarrow\ 1\ \longrightarrow\ 2\ \longrightarrow\ 3

Reaching a depth limit is a cutoff, not proof that the full problem has no solution.

IDS is also called iterative deepening depth-first search. It revisits shallow levels in exchange for depth-first-style memory use. Do not claim BFS-like optimal cost without equal positive action costs. The exact guarantees and the distinction between cutoff and failure are covered in later search lectures.

Informed Search Uses an Estimate

A heuristic h(n) estimates the remaining cost from node n to a goal. Example: straight-line distance in a distance-based road task.

Strategy Priority
Greedy Best-First Search Smallest estimated remaining cost: h(n)
A* Search, pronounced “A-star” Smallest f(n)=g(n)+h(n)
  • g(n): actual cost from the start along this node’s path.
  • h(n): estimated remaining cost, in the same units.
  • f(n): estimated total cost through this node.

For our earlier minutes-based map, h must be measured in minutes, not raw kilometers. Greedy can ignore a very expensive path already taken. A* accounts for that cost too. We will examine which heuristic properties support optimality in Lecture 7; do not imply that an arbitrary estimate guarantees it. A* is an algorithm name, not an abbreviation that expands into words.

Other Ways to Organize Search

Family Central idea Example
Bidirectional search Search from both ends and try to meet Route with a known destination and usable reverse actions
Local search Improve a candidate configuration Move queens to reduce attacks
Adversarial search Account for another player’s choices Choose a chess move against an opponent

The representation and the task determine which search approach makes sense.

These are families rather than a single universal algorithm. Reverse search is not automatic if the goal is a large set or predecessors are hard to generate. Local search often keeps complete candidates rather than paths. Adversarial search deliberately relaxes today’s single-agent assumption. The upcoming course sequence develops each family.

How Do We Judge a Search Algorithm?

Criterion Question
Soundness Is every returned answer a valid solution?
Completeness Will it find a solution whenever one exists?
Optimality Is the returned solution guaranteed least-cost?
Time complexity How much computation is needed?
Space complexity How much memory is needed?

A route reaches G but takes 8 minutes when a 3-minute route exists. Is it valid? Is it optimal?

Answer: valid but not optimal. Guarantees always have assumptions: for example, finite branching, action-cost conditions, and how repeated states are handled. Soundness is about the correctness of returned solutions, not about always finding one. A satisficing approach seeks an acceptable solution without requiring the best one; the user should decide what acceptable means.

Why Search Gets Expensive

Let b be the branching factor (children per node) and d a depth measured in actions.

For a full tree with b=3 and no repeated-state pruning:

Depth d 0 1 2 3 10
Nodes at that depth: b^d 1 3 9 27 59,049

There are 88,573 nodes through depth 10, counting the root and all earlier levels too.

Better representations, pruning, and good search order can matter more than faster hardware.

Here b is constant in an illustrative full tree; real states can have different numbers of successors. The total is 1 + 3 + … + 3^10 = (3^11 - 1) / 2 = 88,573. Distinguish nodes at the last depth from nodes through that depth. Ask what memory pressure looks like if a strategy retains a whole level of pending nodes.

Exit Check: Diagnose the Mistake

  1. A delivery robot stops immediately because it is already Home.
  2. A planner calls an 8-minute route “best” because it uses fewer roads.
  3. A search keeps exploring S → A → S → A → … .

1. Representation / goal test: include package status.

2. Objective: minimize travel time, not action count.

3. Repeated states: recognize equivalent situations instead of exploring the same cycle indefinitely.

Give students one minute to identify the kind of error, then reveal each answer. Follow up: which mistakes require fixing the problem definition, and which require fixing the search procedure? A correct algorithm on the wrong model still solves the wrong task.

Takeaways

  • Define the state, actions, transitions, goal, and costs before searching.
  • A good state remembers exactly what the task needs.
  • A search node records a path to a state; the frontier holds pending nodes.
  • Search strategies trade off solution quality, computation, and memory.
