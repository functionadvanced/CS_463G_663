Pruning Candidate Values

In a constraint satisfaction problem (CSP), propagation removes domain values that cannot belong to a solution.

  • Last time, forced exam slots triggered further deletions.
  • Today: check supports systematically, even before a variable is forced.
  • AC-3 (Arc Consistency Algorithm 3) manages these checks for binary constraints, which involve two variables.

Connect to the four-exam model from Lecture 13. Its final domains are all singleton, but this is not guaranteed for every problem. Domain consistency describes properties of the remaining candidate sets, not just whether the currently assigned variables conflict. The 3 in AC-3 identifies an algorithm, not 3-consistency. Unary restrictions are handled first. Node Consistency

A unary constraint restricts one variable. Node consistency means every remaining value satisfies all its unary constraints.

Let D_X denote the domain of age X, with the rule X\ge18.

Keep D_X=\{20,25,30\}. Having just one valid value is not enough if invalid values remain.

If filtering empties a domain, the current problem or search branch has no solution.

Node consistency is also called 1-consistency. Filtering deletes every value that violates a unary constraint; it does not select a single age. An empty domain after an optional search choice rules out that branch. An empty domain using only the original restrictions rules out the original CSP. Definition checked against the CS50 AI constraint satisfaction notes: https://cs50.harvard.edu/extension/ai/2020/fall/notes/3/ .

Supports for a Binary Constraint

For X<Y, a support for x\in D_X is a value y\in D_Y that makes the constraint true. Lines below join allowed pairs.

X=3 stays: Y=4 is a support because 3<4.

X=4 goes: no value in D_Y is greater than 4.

Original Beamer example. Initial domains: X={1,2,3,4}, Y={2,3,4}. There are six allowed pairs. Every remaining X value needs at least one support, not a distinct support and not compatibility with every Y value. Several X values may use Y=4 as support. A support is a local witness for this one constraint, not a proof that x belongs to a complete solution.

Direction Matters

An arc (X,Y) asks whether each value of X has support in Y. Revising it can shrink X’s domain only.

Directed check After removing 4 from D_X
(X,Y) Each x\in\{1,2,3\} has a larger y
(Y,X) Each y\in\{2,3,4\} has a smaller x

A binary CSP is arc-consistent when every directed arc passes. Reverse the check, not the rule: it is still X<Y.

Node-consistent binary CSPs that satisfy both directions have 2-consistency. Treat multiple constraints on a pair as their combined allowed-pair relation. In the reverse check, C_YX(y,x) expresses x<y, not y<x. Y=2 can use X=1; Y=3 can use X=1 or 2; Y=4 can use X=1,2,3. No Y value is deleted in this example. See https://inst.eecs.berkeley.edu/~cs188/textbook/csp/filtering.html .

REVISE: Remove Unsupported Values

D[i] is the current domain of X_i; C_{ij}(x,y) is true exactly when the pair is allowed.

REVISE(i, j, D, C):
changed ← false
for x in COPY(D[i]):
supported ← EXISTS y in D[j] with C[i,j](x,y)
if not supported:
REMOVE(D[i], x)
changed ← true
return changed
  • COPY lets us delete safely without skipping values during iteration.
  • The return value means “a deletion occurred,” not “a solution exists.”

REVISE mutates D[i], leaves D[j] unchanged, and returns a Boolean change flag. EXISTS stops once one supporting y is found. For the preceding example, REVISE(X,Y) deletes 4 and returns true; an immediate second call makes no change and returns false. The notebook collects values to delete in a separate list, an equally valid way to avoid changing a set during iteration. Pseudocode adapted from the supplied Beamer and AIMA Figure 6.3: https://aima.cs.berkeley.edu/algorithms.pdf .

AC-3: Manage the Pending Checks

Q stores directed arcs awaiting revision. NEIGHBORS(i) lists variables constrained with X_i.

AC3(D, C):
if any D[i] is empty: return false
Q ← queue of all directed arcs (both directions)
while Q is not empty:
(i, j) ← POP_FRONT(Q)
if REVISE(i, j, D, C):
if D[i] is empty: return false
for k in NEIGHBORS(i) except j:
ENQUEUE_IF_ABSENT(Q, (k, i))
return true

A deletion may invalidate neighbors’ supports. true means no empty domain was found, not that a solution was found.

Use a first-in, first-out (FIFO) queue for the trace. Any fair worklist order works; FIFO is not essential for correctness. ENQUEUE_IF_ABSENT avoids duplicate pending arcs, with a set of pending pairs as one implementation. The notebook allows duplicate pending arcs, which can do extra work but does not invalidate propagation. All domains change in place. Initialize with both directions for each combined binary constraint. Skip j on requeue: a removed value in D[i] had no support in D[j], so it could not have been the supporting value for any value in D[j]. This assumes the reverse arc checks the same relation with swapped argument positions. AIMA Figure 6.3 and Berkeley CS188 filtering notes.

AC-3 Trace: First Pass

Rules: A<B and B<C. The queue front is on the left; add an arc only if it is not already pending.

1. (A,B) deletes 3 from D_A: no larger B.

2. (B,A) deletes 1 from D_B: no smaller A.

3. (B,C) deletes 3 from D_B; put (A,B) back.

The initial domains are A={1,2,3}, B={1,2,3}, C={2,3}. Initially Q=[(A,B),(B,A),(B,C),(C,B)]. After step1 Q=[(B,A),(B,C),(C,B)], domains A12 B123 C23. After step2 Q=[(B,C),(C,B)], domains A12 B23 C23; (C,B) is already pending. After step3 Q=[(C,B),(A,B)], domains A12 B2 C23. Ask why A=2, which had support earlier, now needs another check. AC-3 Trace: Rechecking

Continue the same problem and queue. A previously consistent arc may need checking again when its supporting domain shrinks.

4. (C,B) deletes 2 from D_C: B=2 requires C>2.

5. (A,B) deletes 2 from D_A: its old support B=3 is gone.

The queue is empty. Here we obtain a solution: A=1,\ B=2,\ C=3, and both inequalities hold.

After step4, Q=[(A,B)], domains A12 B2 C3. After step5, Q=[], domains A1 B2 C3. This instance happens to become fully solved. Checking (A,B) only once would leave the unsupported value A=2 behind. Domain values never reappear during this run; backtracking, which can restore saved domains, is a separate operation.

Why Incoming Arcs Return

When checking (B,C) removes 3 from D_B, A may lose a support.

  • Recheck (A,B): it asks whether A’s values still have support in B.
  • Checking (B,A) would prune B instead, missing the effect on A.
  • If an affected arc is already in Q, one pending copy is enough.

When D_i shrinks, reconsider arcs into X_i: neighbors were relying on its old values.

Why exclude the immediate reverse (C,B) from new enqueues after REVISE(B,C)? The deleted value B=3 had no compatible C value, so no C value was relying on it. In our trace (C,B) was already pending from initialization, so it is still checked when it reaches the front. Do not remove an existing queue item merely because the requeue rule would not newly add it. The relation is unchanged throughout: B<C.

Arc Consistency Has Limits

Three variables have domains \{1,2\}. Every pair must differ: A\ne B, A\ne C, and B\ne C.

Before any choice, every arc is consistent: 1 has support 2, and 2 has support 1.

Yet there is no solution. Choosing A=1 forces B=C=2; choosing A=2 fails symmetrically.

This is the two-value triangle, not the earlier chain. AC-3 on the original domains makes no deletions and returns true despite unsatisfiability. Different neighbor checks can use supports that cannot coexist globally. Once A is assigned, propagation would eventually produce an empty domain; the highlighted equal B and C values show the contradiction before that final deletion. The original graph is node- and arc-consistent, but not path-consistent. Source: AIMA and standard CSP consistency examples.

Stronger Consistency

Path consistency (3-consistency): every consistent assignment to two variables can be extended to any third variable.

  • k-consistency: every consistent k-1-variable assignment extends to any other variable.
  • Strong k-consistency: all levels 1,2,\ldots,k hold.

Stronger checks detect more contradictions, but cost more.

The pair A=1, B=2 satisfies its own inequality but has no extension to C. Path-consistency algorithms can remove allowed pairs, not just individual domain values. For binary CSPs this is the usual 3-consistency interpretation. Strong n-consistency, where n is the number of variables, permits successive extension without backtracking, but enforcing it is generally too expensive. Do not call every level above 2 path consistency. Source: original Beamer k-consistency definition and https://inst.eecs.berkeley.edu/~cs188/textbook/csp/filtering.html .

Work and Termination

Domains are finite and only shrink. New queue entries are added only after a deletion, so the process eventually stops.

Let e be the number of directed arcs, and d the largest initial domain size.

Work Basic AC-3 bound
One REVISE: try up to d supports for each of d values O(d^2)
Rechecks of one arc as its supporting domain shrinks O(d)
All directed arcs, with duplicate pending entries avoided O(ed^3)

For this chain, what are e and d? e=4, d=3.

Each supporting domain can lose values on at most d separate occasions, and an arc is initially present once. Duplicate suppression keeps at most e arcs pending; queue storage is O(e), in addition to the domains and constraint representation. The simple REVISE implementation scans up to d squared pairs assuming an O(1) constraint test. This analysis is for basic AC-3, not an optimal arc-consistency algorithm. In our worked trace there are five REVISE calls, not e*d^3 calls. Reference: Berkeley CS188 filtering notes.

Takeaways

  • Node consistency: remove values that fail a unary constraint.
  • Arc consistency: each remaining value has support across each binary constraint.
  • REVISE: prune the first variable’s domain.
  • AC-3: revisit affected incoming arcs after deletions.
  • Nonempty domains are not a proof of a solution.

Propagation removes impossible candidates. Search may still be needed to choose values that work together.
