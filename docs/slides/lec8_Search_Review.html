Which Search Fits the Task?

Task What must the answer guarantee?
Fewest moves through an unweighted maze Shortest path
Cheapest route with unequal nonnegative costs Lowest total cost
Cheapest route with a useful lower-bound estimate Lowest total cost with guidance
Any exit in a finite maze A valid path, not necessarily the shortest

Choose an algorithm for each row. Explain what information it uses.

Breadth-first search (BFS), uniform-cost search (UCS), A*, and depth-first search (DFS) are suitable choices, respectively.

The four choices assume finite graphs and appropriate duplicate handling. For the A* choice, a consistent heuristic permits finalizing states on removal. An admissible but inconsistent heuristic requires reopening improved paths. DFS is one suitable choice when any route suffices, although BFS would also find a valid route. Search terminology follows AIMA Chapter 3 and https://inst.eecs.berkeley.edu/~cs188/textbook/search/informed.html.

One Graph, Several Search Orders

Start at S. Find a route to G. Edges are directed and labels are costs.

There are three S-to-G paths: S-A-G has two edges and cost 10, S-B-G has two edges and cost 6, and S-A-C-G has three edges and cost 5. The fewest-edge answer is not unique.

BFS: Trace the Queue

Add unreached successors alphabetically. Remove from the left and test for the goal.

Removed Queue after processing Parent update
S [A,B] A\gets S, B\gets S
A [B,C,G] C\gets A, G\gets A
B [C,G] Keep G\gets A
C [G] Keep G\gets A
G stop Follow parents backward

Initial queue: [S].

An already reached state keeps its first parent.

Returned path: S\to A\to G. Two edges, but cost 1+9=10. BFS minimizes the number of edges, not arbitrary edge costs.

DFS: Trace the Current Path

Use recursive-style DFS: enter the alphabetically first unvisited successor.

Enter Current path
S [S]
A [S,A]
C [S,A,C]
G [S,A,C,G]

No backtracking is needed in this run.

DFS returns a path of cost 1+2+2=5. Does this establish that DFS is optimal?

No. If DFS explores G before C at A, it returns the cost-10 path. Its first answer depends on successor order.

An explicit stack of DFS frames can reproduce this recursive order. For a simpler stack of nodes, reverse insertion order gives alphabetical removals only when duplicate handling permits it. Marking all siblings reached as soon as they are pushed can change the parent tree: marking G while expanding A could prevent C from later entering G. Distinguish the active path shown here from the entire pending-node stack.

UCS: Update a Better Path

g is the queued path’s cost. best[n] stores the cheapest cost found for state n.

S:0 A:1,\ B:4
A:1 C:3,\ B:4,\ G:10
C:3 B:4,\ G:5

After expanding C:

best[G]: 10\to5.

Discovering G at cost 10 does not finish the search. Removing it at the minimum frontier cost does.

Greedy Search Versus A*

h(n) estimates the remaining cost. These values are consistent on this graph.

State S A B C G
h(n) 5 4 2 2 0

After expanding S, both searches have A and B on the frontier.

Greedy best-first search

Priority: h(n).

Choose B: h(B)=2<h(A)=4. Then choose G.

Path cost: 4+2=6.

A* search

Priority: f(n)=g(n)+h(n).

f(A)=1+4=5.
f(B)=4+2=6.

Choose A, then C and G. Path cost: 5.

Heuristic Check

  1. Is h(A)=4 admissible? What about h(A)=8?
  2. If all heuristic values are zero, which algorithm does A* become?
  3. Can greedy search return a suboptimal path even with an admissible heuristic?

True remaining costs:

h^*(A)=4, h^*(B)=2, h^*(C)=2.

  1. Yes for 4, no for 8: admissibility requires 0\le h(n)\le h^*(n).
  2. UCS, since f(n)=g(n).
  3. Yes: our greedy path costs 6, while the optimum costs 5.

Correctness Depends on the Implementation

Assume a finite graph and nonnegative edge costs.

Situation What the implementation needs
Cycles in a finite graph Duplicate detection
UCS finds a cheaper path Update the best cost and parent
A* with a consistent heuristic An expanded state need not reopen
A* with an admissible but inconsistent heuristic Allow reopening when a better path appears

Consistency: for every edge n\to n' with cost c,

h(n)\le c+h(n'),\qquad h(G)=0.

For UCS and A*, retain improved routes and accept a goal when its current entry leaves the priority queue.

Finite graph and nonnegative edge costs throughout this review. Admissibility suffices for A* tree search under standard termination conditions. Graph search that permanently closes states needs consistency, or it must support reopening. Consistency is stronger than simply being a lower bound.

Big-O Notation

Big-O ignores constant factors and lower-order terms as input size grows.

A function f(n) is O(g(n)) if there exist positive constants c and n_0 such that

0\le f(n) \le c \cdot g(n)

for every n\ge n_0.

For n\ge1, 3n^2+5n+7\le15n^2. Choose c=15 and n_0=1 to show O(n^2).

State whether a bound describes the worst case, average case, or another case. Big-O alone does not specify which.

Graph Representation Matters

Let V be the number of vertices and E the number of edges in a finite graph.

Representation Stored graph Full BFS/DFS traversal
Adjacency list O(V+E) O(V+E)
Adjacency matrix O(V^2) O(V^2)

For A, a list stores just (C,2) and (G,9).

A matrix row checks all five possible destinations, including absent edges.

For a sparse graph, most matrix entries describe no edge.

Bounds describe a traversal covering all vertices, starting additional traversals for disconnected components if necessary. In a single-source search, only reached vertices need their neighbors scanned. Absent matrix edges need a sentinel distinct from legitimate zero-cost edges. The graph’s adjacency lists contain 6 total entries. A 5 by 5 matrix has 25 entries. Graph storage is separate from additional search records.

BFS Complexity

Mark each state reached on insertion, so each vertex enters the queue at most once.

Time

  • Expands each reached vertex and scans its adjacency list.
  • O(V+E) with adjacency lists.
  • O(V^2) with adjacency matrices.

Additional search space

  • Queue, reached set, and parents use O(V).
  • The queue can contain parts of two adjacent layers.
  • A wide last layer can dominate memory.

A complete tree with branching factor b>1 and maximum depth d has b^d leaves. BFS may need O(b^d) frontier space on that tree.

These are worst-case traversal bounds and exclude the stored graph from additional search space. Here d is the maximum depth of a finite complete tree, not the solution-depth convention in an unbounded search tree. Goal testing on removal in an implicit tree can generate the next layer before stopping, so state that convention when comparing textbook b-to-the-d formulas. Reference: AIMA Chapter 3 and https://inst.eecs.berkeley.edu/~cs188/textbook/search/uninformed.html.

DFS Complexity

Mark a vertex when entering it and skip already visited vertices.

Time

  • Expands each reached vertex and scans its adjacency list.
  • O(V+E) with adjacency lists.
  • O(V^2) with adjacency matrices.

Stack versus visited set

  • A chain can require O(V) active calls.
  • A balanced tree needs O(\log V) active calls.
  • A graph-search visited set still uses O(V).

Recursive DFS uses O(V) additional space in a general graph. A shallow call stack alone does not make the entire search use O(\log V) space.

The recursion-stack bound assumes adjacency-list iterators or equivalent DFS frames, so each level records its next neighbor rather than copying all remaining neighbors. A tree traversal needs no visited set when parent/child direction already prevents cycles. A node-stack implementation with repeated pending entries can have a different memory bound. Keep implementation assumptions explicit.

UCS, Greedy, and A*

For a finite explicit graph, let V be vertices and E be edges.

Algorithm Priority Assumption for the usual bound
UCS g Nonnegative edge costs
Greedy h Expand each state at most once
A* g+h Consistent heuristic, no re-expansion

With adjacency lists and a binary heap holding one entry per frontier state:

\text{Time}=O((V+E)\log V),\qquad \text{storage}=O(V+E).

Decrease-key lowers an existing entry’s priority and restores heap order in O(\log V), using an index to locate that entry.

Storage includes the graph. Reopening states or retaining stale heap entries requires extra accounting.

With an indexed binary heap, insert, pop, and decrease-key cost O(log V). Up to V state removals and E examined edges give O((V+E)log V) time with constant-time edge/heuristic evaluation. The total O(V+E) space includes the graph; the heap, parent, and best arrays use O(V). A lazy heap can hold O(E) entries and gives O((V+E)log(V+E)) directly; on a simple graph this has the usual O((V+E)log V) form because E is at most V squared. A* with inconsistent heuristics can re-expand states, so those assumptions no longer suffice. Greedy’s bound here assumes duplicate control, not optimality.

A* and Heuristic Quality

Let d be the solution depth and C^* the optimal total cost.

Weak Heuristic

  • h(n)=0 gives exactly UCS priorities.
  • Many low-cost prefixes can look promising.

Strong Heuristic

  • A tighter lower bound can rule out more unpromising routes.
  • Even an exact heuristic may leave many tied optimal paths.

If two different optimal routes have the same total cost C^*, what can their frontier priorities be when h=h^*?

Both can have f=C^*. Tie-breaking and heuristic evaluation cost still matter, so a perfect heuristic does not guarantee O(d) runtime.

A Graph Bound Can Still Hide Exponential Work

Suppose a complete search tree has branching factor b=3 and maximum depth d=10. The root has depth 0.

Depth 0 1 2 3 \cdots 10
Nodes in the layer 1 3 9 27 \cdots 59,049

\text{Leaves}=3^{10}=59{,}049,\qquad \text{total nodes}=\sum_{i=0}^{10}3^i=88{,}573.

How can traversal be linear in V+E and exponential in depth?

The number of vertices V itself grows exponentially with d. Always state what the input-size variable measures.

Exit Problem: Two Correctness Bugs

A UCS implementation uses the shown graph but makes these choices:

  1. Add a new state to a permanent visited set when generating it.
  2. Ignore every later path to that state.
  3. Return immediately when generating a goal.

Which route does it return? If only the goal test is fixed, does the other bug remain?

Early goal test: expanding A returns cost 10 immediately.

Permanent visited-on-generation: even with a goal test on removal, it rejects the later route through C costing 5.
