One Graph, Several Search Orders

Edges are directed. Labels are costs. Start at S and finish at G.

  • Visit successors alphabetically. In DFS, visit A before B.
  • Test for the goal when removing a node from the frontier.
  • For BFS, mark a state reached when adding it to the queue.

BFS: Trace the Queue

The leftmost entry leaves the queue next. Keep the first parent of each state.

Removed Queue after expansion New parent links
S [A,B] A\gets S, B\gets S
A [B,C,G] C\gets A, G\gets A
B [C,G] G is already reached
C [G] G is already reached
G stop Follow parents backward

Returned path: S\to A\to G. Two edges, but cost 1+9=10. BFS minimizes the number of edges, not arbitrary edge costs.

DFS: Trace the Current Path

Choose the alphabetically first unvisited successor at each step.

[S]\quad\longrightarrow\quad[S,A]\quad\longrightarrow\quad [S,A,C]\quad\longrightarrow\quad[S,A,C,G]

DFS returns a path of cost 1+2+2=5. Does this establish that DFS is optimal?

No. If DFS explores G before C at A, it returns the cost-10 path. Its first answer depends on successor order.

For an iterative stack, push successors in reverse order to visit them alphabetically.

UCS: Update a Better Path

g(n) is the cost of the best path found so far to n.

Removed Logical frontier, ordered by g
S:0 A:1,\ B:4
A:1 C:3,\ B:4,\ G:10
C:3 B:4,\ G:5
B:4 G:5 (the new candidate costs 6)
G:5 Stop with S\to A\to C\to G

Discovering G at cost 10 does not finish the search. Removing it at the minimum frontier cost does.

This table shows one best entry per state. A heap implementation may retain the old G:10 entry and skip it as stale later. Ask students to identify when the parent of G changes from A to C. Edge costs are nonnegative.

Greedy Search Versus A*

h(n) estimates the remaining cost. Use these values on the same graph:

State S A B C G
h(n) 5 4 2 2 0

Greedy best-first search

Priority: h(n).

After S, choose B over A because 2<4. Then choose G.

Path cost: 4+2=6.

A* search

Priority: f(n)=g(n)+h(n).

After S, f(A)=1+4=5, while f(B)=4+2=6.

Continue through C to G. Path cost: 5.

Heuristic Check

True remaining costs: h^*(A)=4, h^*(B)=2, h^*(C)=2.

  1. Is h(A)=4 admissible? What about h(A)=8?
  2. If all heuristic values are zero, which algorithm does A* become?
  3. Can greedy search return a suboptimal path even with an admissible heuristic?
  1. Yes for 4, no for 8: admissibility requires 0\le h(n)\le h^*(n).
  2. UCS, since f(n)=g(n).
  3. Yes: our greedy path costs 6, while the optimum costs 5.

Correctness Depends on the Implementation

Situation What the implementation needs
Cycles in a finite graph Duplicate detection
UCS finds a cheaper path Update the best cost and parent
A* with a consistent heuristic An expanded state need not reopen
A* with an admissible but inconsistent heuristic Allow reopening when a better path appears

Consistency: for every edge n\to n' with cost c,

h(n)\le c+h(n'),\qquad h(G)=0.

Finite graph and nonnegative edge costs throughout this review. Admissibility suffices for A* tree search under standard termination conditions. Graph search that permanently closes states needs consistency, or it must support reopening. Consistency is stronger than simply being a lower bound.

Big-O Notation

  • Big-O describes an upper bound on time or space growth.
  • It focuses on large inputs.
  • It hides constant factors and lower-order terms.

A function f(n) is O(g(n)) if there exist positive constants c and n_0 such that

f(n) \le c \cdot g(n), \quad \forall n \ge n_0.

From Binary Search to KD-Trees

Binary search works because a sorted line can be split in half.

A k-dimensional tree (KD-tree) extends that idea to points in space:

Search structure Split rule Good for
Binary search one sorted dimension ordered keys
KD-tree alternate coordinate axes spatial points

KD-Tree Nearest Neighbor

A KD-tree is useful when many queries ask: “Which stored point is closest to this query point?”

Search idea

  1. Follow the split decisions to a leaf.
  2. Keep the best point found so far.
  3. Backtrack only into regions that could contain a closer point.

Complexity intuition

  • Favorable low-dimensional data: queries are often near O(\log n).
  • Worst case: O(n), even with a balanced tree.

High dimensions can weaken pruning.

The same “split and ignore irrelevant half” idea behind binary search becomes spatial pruning in a KD-tree.

KD-Tree: Can We Prune This Region?

Query q=(4,3). Best point so far: p=(3,3), at distance 1.

The split is |6-4|=2 units away, greater than 1. No point on the right can improve the answer.

Ask what changes if the query moves to x=5.5 and the current best distance is still 1. The lower bound becomes 0.5, so this pruning test no longer rules out the right region. It does not guarantee that the right region contains a better point.

Graph Representation Matters

Representation Neighbor lookup style Common cost
Adjacency list iterate only actual neighbors O(V+E) traversal
Adjacency matrix scan possible neighbors O(V^2) traversal

When reviewing search complexity, always ask: “How is the graph represented?”

BFS Complexity

Time

  • Expands each reached vertex and scans its adjacency list.
  • O(V+E) with adjacency lists.
  • O(V^2) with adjacency matrices.

Space

  • Stores the frontier by layers.
  • O(V) for general graphs.
  • O(b^d) for trees with branching factor b and depth d.

DFS Complexity

Time

  • Expands each reached vertex and scans its adjacency list.
  • O(V+E) with adjacency lists.
  • O(V^2) with adjacency matrices.

Space

  • Stores the current path and pending alternatives.
  • Can be O(V) in a long path.
  • Recursion depth is O(\log V) for a balanced tree.

UCS, Greedy, and A*

For a finite explicit graph, let V be vertices and E be edges.

Algorithm Priority Assumption for the usual bound
UCS g Nonnegative edge costs
Greedy h Expand each state at most once
A* g+h Consistent heuristic, no re-expansion

With adjacency lists and a binary heap supporting decrease-key:

\text{Time}=O((V+E)\log V),\qquad \text{storage}=O(V+E).

The bound includes the stored graph. Reopening states or generating a huge implicit state space changes the analysis.

A* Best and Worst Cases

Weak Heuristic

  • If h(n) gives little useful guidance, A* behaves much like UCS.
  • It may expand many nodes.

Strong Heuristic

  • If h(n) is very accurate, A* can move almost directly toward the goal.
  • Even an exact heuristic may leave many tied optimal paths to explore.

A Graph Bound Can Still Hide Exponential Work

Suppose a search tree has branching factor b=3 and depth d=10.

\text{Leaves}=3^{10}=59{,}049,\qquad \text{total nodes}=\sum_{i=0}^{10}3^i=88{,}573.

How can traversal be linear in V+E and exponential in depth?

The number of vertices V itself grows exponentially with d. Always state what the input-size variable measures.

Complexity Practice

Question Your estimate
V=1{,}000, E=3{,}000: adjacency-list traversal? In terms of V+E
Same graph: adjacency-matrix traversal? In terms of V^2
Double n: an O(n^2) leading term changes by what factor? Ignore lower-order terms
A chain of V vertices: maximum recursive DFS depth? Count active calls

About 4,000 vertex/edge visits versus 1,000,000 matrix entries, a factor of 4, and depth V. These are operation-scale estimates, not runtime measurements.

Exit Problem: Find the First Bug

A weighted-search implementation does this:

  1. Add a new state to a permanent visited set when generating it.
  2. Ignore every later path to that state.
  3. Return immediately when generating a goal.

Use today’s graph to explain two ways this can lose the cheapest path.

It can freeze G at cost 10 and reject the later cost-5 route. It can also stop at cost 10 before removing the cheapest goal from the priority queue.

Review Checklist

  • What counts as a state?
  • What is the branching factor?
  • Is the graph weighted?
  • Is the search using a queue, stack, or priority queue?
  • Does the algorithm need to store many frontier nodes?
  • Is the goal shortest path, lowest cost, or merely any solution?
