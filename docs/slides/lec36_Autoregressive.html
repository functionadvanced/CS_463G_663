One Piece at a Time

An autoregressive (AR) model predicts each piece of an ordered sequence from its earlier pieces, called the prefix. “Auto” refers to the history of the same sequence; outputs need not be numeric regression targets.

A token is a text piece, such as a word or part of a word. We use one word per token in our toy examples.

A modality is a form of data. Text tokens and image pixels can both be ordered into sequences.

During generation, the model’s sampled outputs become part of the next input.

The lecture develops the supplied Spring 2025 autoregressive-model material. The diagrams and probabilities are constructed examples, not outputs of a trained language model. Real tokenizers need not split at word boundaries. Autoregression specifies conditional dependence along an ordering; it does not require an RNN or a numeric regression loss. Training can use observed prefixes rather than sampled ones, as explained under teacher forcing.

The Probability Chain Rule

Let x_1,\ldots,x_T be a sequence of length T. Write x_{<t} for the pieces before position t, and \theta for learned model parameters.

p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}).

For three pieces, this means

p_\theta(x_1,x_2,x_3)=p_\theta(x_1)\, p_\theta(x_2\mid x_1)\, p_\theta(x_3\mid x_1,x_2).

The first factor has no earlier piece to condition on. A conditional generator can also include a prompt in every factor.

The chain rule does not assume independent pieces. We learn conditional distributions that can depend on the earlier context.

The factorization is an identity for any joint distribution, on prefixes with positive probability. A particular architecture can restrict how much context it effectively uses. For variable-length sequences, include termination in the modeled sequence; a length budget can separately bound decoding. A fixed prompt is a condition, not an additional probability factor when calculating the probability of a completion given that prompt.

A Completion Probability

Fix the prompt “The sky is”. A special end-of-sequence (EOS) token tells the generator to stop.

Suppose a toy model assigns probability 0.6 to blue after this prompt, then probability 0.8 to EOS after “The sky is blue”.

What is the probability of this complete two-token continuation?

p_\theta(\text{blue},\text{EOS}\mid\text{The sky is})=0.6\times0.8=0.48. The second probability uses the updated prefix. This is not the probability of the prompt itself.

Only one branch is drawn. Other next-token outcomes have the remaining mass at each prefix. The initial color distribution used in the next slide is blue .6, gray .3, green .1. After blue, EOS has probability .8 and a possible longer continuation has total probability .2. The probability of just the first token blue is .6; the probability of blue followed immediately by termination is .48.

Sampling and Greedy Decoding

Decoding selects outputs from the model’s distributions. Greedy decoding picks the highest-probability token. Sampling makes a random choice using those probabilities.

For a color-only choice after “The sky is”, use this toy distribution:

Draw u uniformly from [0,1). What token does u=0.75 select, and what would greedy decoding choose?

Sampling selects gray; greedy decoding selects blue. Greedy choices do not necessarily give the most probable complete sequence.

The probabilities sum to one. The half-open intervals place .6 in gray and .9 in green. Greedy decoding optimizes the current choice, not the full product of later conditionals. This slide does not claim that random sampling guarantees useful or correct content. Temperature and truncated sampling can be introduced separately when needed.

The Generation Loop

Start with a prompt. maxNewTokens is a chosen limit on how many additional tokens may be generated.

sequence = Copy(prompt)
for t = 1, …, maxNewTokens
distribution = Model(sequence)
token = Sample(distribution)
if token == EOS: break
Append(sequence, token)
return sequence

The model’s parameters stay fixed. Each new distribution conditions on the actual prefix accumulated so far.

Stop at EOS or the length limit. Sampling does not guarantee that EOS will arrive quickly.

This is architecture-independent pseudocode. The returned sequence includes the prompt and excludes EOS. No later call is made after an EOS sample. An RNN can cache and update its hidden state rather than recomputing every prefix from scratch. A Transformer can cache intermediate representations. Those optimizations do not change the conditional sampling logic.

Training with the Correct Prefix

Teacher forcing trains next-token predictions using the true earlier tokens from a dataset, rather than the model’s sampled earlier tokens.

Average negative log-likelihood (NLL) on a training sequence is

L(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).

EOS is also a target. Each prediction sees only the earlier tokens.

Generation uses sampled prefixes, so early mistakes can change later predictions.

The examples show three positions from a longer sequence. Training also handles the initial-token and termination predictions. NLL is the same likelihood principle introduced in Lecture 35, applied to conditional token probabilities. Full sequence training can evaluate many target positions together when the architecture permits it; a standard RNN still has sequential hidden-state dependencies. A known full training sentence does not authorize using future tokens in a next-token prediction.

Recurrent Neural Networks

A recurrent neural network (RNN) repeatedly updates a hidden state h_t, a fixed-size vector summarizing the prefix. The same update parameters are reused at every position.

An embedding e_t is a learned numeric vector representing input token x_t:

h_t=F_\theta(e_t,h_{t-1}).

After reading x_t, state h_t helps predict x_{t+1}. The state need not preserve every detail of the prefix.

The diagram is an unrolled view: three applications of one parameter-shared update, not three separately trained models. The initial state h0 is specified or learned; the numerical example uses zero. An output head converts states into token probabilities. RNNs can also serve classification tasks; the recurrent architecture itself is not inherently generative. Reference: https://docs.pytorch.org/docs/stable/generated/torch.nn.RNN.html.

A Small Recurrent Update

Use a toy scalar state instead of a vector:

h_t=\tanh(0.5h_{t-1}+e_t).

The hyperbolic tangent, \tanh, maps real inputs into (-1,1). Here the chosen weights and token inputs are illustrative, not learned from text.

Starting at h_0=0, let the input for The be e_1=1: h_1=\tanh(1)\approx0.762.

For sky, let e_2=0.5. What is h_2?

h_2=\tanh(0.5\times0.762+0.5)\approx0.707. The update combines old context with the new input.

Using the unrounded h1 gives h2 approximately .706818. The recurrent coefficient is .5 and the input coefficient is 1, with zero bias. In a real model these are learned matrices and vectors. These scalar inputs are a separate recurrence calculation, not a claim that a real embedding assigns these values to the displayed words.

Hidden States to Token Probabilities

An output head assigns a logit, or unnormalized score a_j, to token j. The vocabulary is the set of V allowed tokens.

Softmax gives token j’s probability p_j:

p_j=\frac{e^{a_j}}{\sum_{k=1}^{V}e^{a_k}}.

In this three-color illustration, logits (\log6,\log3,0) give exponentials (6,3,1). Dividing by their sum 10 gives (0.6,0.3,0.1).

This is a restricted three-color output head illustrating normalization, not the complete vocabulary of a language generator. A full text generator also needs tokens for other words and termination. The logits are stipulated, not derived from the separate scalar RNN exercise. Natural logarithms are used. For numerical stability, real implementations subtract the maximum score before exponentiating, or use log-softmax. Adding the same constant to all logits does not change softmax.

Long Dependencies and Gradients

A dependency is a relationship between sequence positions. Here the singular subject key calls for is, despite the nearer plural word cabinets.

Training backpropagates through repeated state updates. Vanishing gradients shrink the learning signal to earlier steps; exploding gradients make it grow excessively.

Repeated derivative factors illustrate the issue:

0.5^{10}\approx0.001,\qquad 1.5^{10}\approx57.7.

Recurrent memory must retain relevant information through many updates. Gated architectures help control that information flow.

The sentence illustrates a grammatical relationship, not a measured language-model failure. The powers are scalar illustrations of gradient products, not a claim that every RNN repeatedly multiplies by a fixed scalar. Hidden-state compression and gradient propagation are related challenges but not identical phenomena. Gates do not guarantee perfect long-term memory or solve all optimization problems.

Long Short-Term Memory

Long Short-Term Memory (LSTM) is a gated recurrent architecture. It carries a cell state c_t as a memory path, alongside hidden state h_t used for prediction.

A gate controls information flow component by component. Sigmoid \sigma(v)=1/(1+e^{-v}) produces values between 0 and 1.

  • Forget gate f_t: keep old cell memory.
  • Input gate i_t: write proposed content g_t, the candidate produced with \tanh.
  • Output gate o_t: expose transformed cell memory as hidden state.

The state diagram shows the two memory roles and the core update, rather than every connection used to compute each gate. All gates and the candidate depend on current input and previous hidden state. The next slide states those computations, including the output gate. Gate values are vectors in a real model. Reference: https://docs.pytorch.org/docs/stable/generated/torch.nn.LSTM.html.

LSTM Updates and a Worked Step

Let v_t=[e_t;h_{t-1}]: concatenation appends the two vectors. The W matrices and b bias vectors below are learned parameters; \odot means elementwise multiplication.

\begin{aligned} f_t&=\sigma(W_fv_t+b_f),& i_t&=\sigma(W_iv_t+b_i),\\ o_t&=\sigma(W_ov_t+b_o),& g_t&=\tanh(W_gv_t+b_g),\\ c_t&=f_t\odot c_{t-1}+i_t\odot g_t,& h_t&=o_t\odot\tanh(c_t). \end{aligned}

For one scalar component, suppose c_{t-1}=0.8 and the computed gate/candidate values are f_t=0.9, i_t=0.2, g_t=0.5, o_t=0.7.

c_t=0.9(0.8)+0.2(0.5)=0.82, h_t=0.7\tanh(0.82)\approx0.473. Keeping memory and exposing it are different operations.

Concatenating the input and previous hidden state combines the separate input-to-state and hidden-to-state affine maps into one matrix per gate. Biases can likewise be combined. The output-gate equation is required for the displayed h update. The numerical gates and candidate are assumed outputs of their learned maps; this is not a calculation of those values from a supplied input. This shows a standard non-peephole, non-projected LSTM. The direct cell path helps regulate gradient propagation but is not a guarantee against forgetting.

Gated Recurrent Units

A gated recurrent unit (GRU) has one recurrent hidden state, without a separate LSTM-style cell state.

  • The reset gate r_t controls use of old state when computing candidate n_t.
  • The update gate z_t blends the candidate and old state. Using the PyTorch convention,

h_t=(1-z_t)\odot n_t+z_t\odot h_{t-1}.

h_t=0.1(0.1)+0.9(0.8)=0.73. In this convention, an update gate near 1 preserves more old state.

Some sources reverse the naming or complement of the update coefficient; the displayed equation fixes the convention. The reset and update gates are learned sigmoid outputs, and n is a tanh candidate. The reset gate influences the candidate, not the final blend coefficient. PyTorch’s placement of the reset gate inside its candidate computation differs slightly from the original GRU formulation. This introductory slide does not compare speed or accuracy across architectures. Reference: https://docs.pytorch.org/docs/stable/generated/torch.nn.GRU.html.

Images as Ordered Sequences

PixelCNN uses a convolutional neural network (CNN) to predict pixels autoregressively. Raster order means left to right across each row, then top to bottom.

For this four-pixel image,

p(x_1,x_2,x_3,x_4)=p(x_1)p(x_2\mid x_1)p(x_3\mid x_1,x_2)p(x_4\mid x_1,x_2,x_3).

The image is spatial data; the generation procedure imposes an ordering on it.

Aaron van den Oord, Nal Kalchbrenner, and Koray Kavukcuoglu (2016), Pixel Recurrent Neural Networks. The paper also introduces PixelCNN.

The example is binary and single-channel, avoiding RGB channel ordering. The original PixelCNN uses discrete pixel-channel predictions and masked convolutions. The displayed factorization specifies permitted dependence; a finite convolutional receptive field may capture only part of the full preceding context. The diagram is a constructed image, not a generated sample from a trained PixelCNN.

Causal Masks Prevent Peeking

Causal prediction uses earlier positions, not the target or future values. A mask fixes selected convolution weights to zero so forbidden inputs cannot affect the prediction.

At the raw-input layer, the current pixel must also be excluded. Otherwise the network could copy the answer it is supposed to predict.

Training knows the full image, but predictions must respect the mask. Generation still fills pixels in order.

The displayed spatial mask is the single-channel first-layer, type-A idea. Later type-B masks can include the current hidden position without exposing the raw target value, provided all earlier layers preserve causality. Color channels require an additional within-pixel ordering. A correct local mask does not imply an unlimited receptive field. PixelCNN can evaluate many training positions in parallel, but ordinary sampling has sequential dependencies. Source: van den Oord et al., Sections 2.1, 3.4, and 3.5.

A Pixel-by-Pixel Probability

A and C start with 1: 0.5+0.2=0.7. Only A has prefix (1,1), giving conditional probability 0.5/0.7=5/7 for the second pixel.

Event along the branch for A Conditional probability
x_1=1 0.7
x_2=1 given x_1=1 5/7
(x_3,x_4)=(0,0) given prefix (1,1) 1\times1

p(A)=0.7\times(5/7)\times1\times1=0.5.

This is the exact categorical distribution from Lecture 35, expressed autoregressively rather than obtained by fitting a PixelCNN. A=(1,1,0,0), B=(0,0,1,1), and C=(1,0,0,1). Under the first-pixel-one branch, the masses of A and C are .5 and .2; normalizing gives 5/7 and 2/7. Once the prefix is (1,1), only A remains. This example does not assume independent pixels and does not claim that a particular local mask learns every dependency exactly.

One Factorization, Different Architectures

Autoregression specifies which context is allowed. The architecture determines how that context is represented.

Architecture How it uses the prefix
Basic RNN One recurrent hidden-state vector
LSTM Hidden state plus gated cell memory
GRU One gated recurrent state
PixelCNN Masked convolutions over earlier pixels
Transformer decoder Attention over earlier token representations

Attention forms weighted combinations of representations. The next lecture develops this idea for Transformers.

Stacking recurrent layers adds depth at each position; each layer still maintains its own state across positions.

Architectures are not interchangeable performance guarantees. A Transformer decoder used autoregressively must prevent future-token access. Attention and its query/key/value mechanics are introduced in the next lecture, rather than assumed here. Stacking is distinct from stepping through time. A recurrent network can also be bidirectional for non-autoregressive tasks; such future access would violate the left-to-right conditional model illustrated here.

Quick Check

  1. At generation time, should the next input use a sampled token or an unavailable correct answer?
  2. Is the LSTM cell state c_t the same object as its hidden state h_t?
  3. Can an autoregressive image model predict a pixel using that same raw pixel as input?

1. The sampled token. Teacher forcing uses correct earlier tokens during training, not ordinary generation.

2. No. The cell carries memory; the output gate controls how it is exposed as the hidden state.

3. No. That leaks the target. The causal mask must block it.

Takeaways

  • Autoregressive models factor a sequence probability into conditional probabilities.
  • Training uses known next-token targets; generation repeatedly chooses and appends outputs.
  • EOS and a length budget give explicit stopping rules.
  • RNNs summarize the prefix; LSTMs and GRUs control recurrent information with gates.
  • PixelCNN imposes an ordering and masks forbidden pixel inputs.
  • The same generation principle can use different neural architectures, including Transformers.
