Cheapest, Not Shallowest

Breadth-first search (BFS) minimizes the number of edges.

The direct route S \to G has one edge, but costs 12.

Uniform-cost search (UCS) minimizes the sum of edge costs.

S \to B \to A \to C \to G costs 2+1+1+2=6.

Fewer actions do not necessarily mean a cheaper solution.

Recall the FIFO queue from Lecture 5. Ask which objective BFS optimizes before comparing the two routes. All arrows in this lecture’s worked graph are directed; only the eight drawn edges exist. Reserve about 8 minutes near the end for the existing UCS notebook and allow time for HW1 questions.

The Priority Is the Cost So Far

g(n)=\sum_{\text{edges on the current path to }n} c(u,v)

  • g(n) is the cost of a particular path found so far, not a guess of the remaining cost.
  • A min-priority queue removes an entry with the smallest g.
  • UCS is uninformed: it uses no estimate of distance to the goal.
After expanding S Path cost g Depth
S \to B 2 1
S \to A 6 1
S \to G 12 1

With equal positive edge costs, ordering by cost is ordering by depth, as in BFS.

A Better Route Can Arrive Later

First discovery: S \to A, cost 6.

Later discovery: S \to B \to A, cost 3.

\begin{aligned} \text{candidate} &= g(B)+c(B,A) \\ &=2+1=3<6. \end{aligned}

Relaxation: replace a recorded route when the candidate is cheaper. Update its cost and parent together.

Unlike BFS with unit costs, UCS cannot finalize a node when it is first discovered.

UCS Pseudocode: Choose a Node

cost: the popped entry’s stored cost. best[u]: the cheapest cost found so far for u.

UCS(graph, start, goal)
best <- default_map(infinity); best[start] <- 0
parent[start] <- None; Q <- min_priority_queue()
push(Q, (0, start))
while Q is not empty:
(cost, u) <- pop_min(Q)
if cost != best[u]: # Skip an obsolete queue entry
continue
if u == goal:
return reconstruct(parent, goal), cost
RELAX_NEIGHBORS(graph, u, cost, best, parent, Q)
return failure

Old entry (6, A) still records 6, but best[A] is now 3. Skip the old entry when it is removed.

Explain that best is a dictionary with infinity as its default in an implicit state space; no enumeration of all states is necessary. Parent stores the predecessor for reconstruction. This version inserts a new heap entry on a strict improvement rather than modifying an existing entry. Inserting (3, A) changes best[A] but does not edit or remove the older (6, A) entry. The cheaper entry is removed first; when the older one reaches the front, the cost mismatch identifies it as stale. Nonnegative costs and strict improvements ensure a current entry finalizes its node without needing a separate finalized set. The notebook uses an equally valid visited-on-pop variant instead. The later duplicate-handling slide explains that this particular check is an efficiency guard, not a universal requirement of UCS.

UCS Pseudocode: Improve Its Neighbors

For each outgoing edge u\to v, compare the new route against the stored cost.

RELAX_NEIGHBORS(graph, u, cost, best, parent, Q)
for each edge (u, v) with weight w in graph:
candidate <- cost + w
if candidate < best[v]:
best[v] <- candidate
parent[v] <- u
push(Q, (candidate, v))

At B: the candidate for A is 2+1=3. Replace best[A] = 6 with 3, set parent[A] = B, and insert (3, A).

The strict comparison avoids reinserting equal-cost routes, including around zero-cost cycles.

What About Old Queue Entries?

Inserting (3, A) does not remove the older (6, A). After processing C, the heap can still contain:

Entry, in removal order Current best cost Action
(6, A) 3 Skip: superseded by a cheaper route
(6, C) 4 Skip: superseded by a cheaper route
(6, G) 6 Accept: current entry for the goal
(10, G), (12, G) 6 Never needed after UCS returns

Equal costs are ordered alphabetically here. The table is sorted for explanation; a heap’s internal array is not fully sorted.

An obsolete entry is a stale entry. Removing one is not a new node expansion.

Contrast the logical frontier on the trace slide with physical heap contents. Right after C, the sorted entries are exactly A:6, C:6, G:6, G:10, G:12 for the strict-improvement implementation. Other Ways to Handle Duplicate Entries

Assume nonnegative edge costs. The exact cost != best[u] check is not required in every UCS implementation.

Method How repeated work is avoided
Cost check (these slides) Insert improved entries; skip an entry whose stored cost differs from best[u].
Finalized set (notebook) On removal, skip a node already finalized; otherwise finalize it and test the goal.
Decrease-key Keep one pending entry per node and lower its priority on improvement. No obsolete entry remains.

In this pseudocode, strict cost-improvement updates already make stale expansions redundant. Removing the check keeps the correct result, but can waste work.

For UCS, finalize a node on removal, not when it is first discovered.

These are alternatives, not three checks that must all be used together. In the current pseudocode, (3, A) is removed before (6, A), and all outgoing edges of A have already been relaxed using cost 3. Relaxing them again from cost 6 cannot beat the recorded costs, because updates require a strict improvement. Thus skipping the stale entry avoids redundant neighbor scans; omitting this guard does not change the answer under the stated assumptions. This observation is specific to this strict-improvement implementation, not to arbitrary search code. A finalized set is correct with nonnegative costs only when nodes are finalized on removal. Marking A at its first discovery with cost 6 would incorrectly block the route of cost 3. Python’s heapq has no built-in decrease-key operation, which is why inserting a new entry and later skipping duplicates is convenient. The notebook’s visited set implements finalized-on-pop, and its goal test follows the duplicate check.

Why Cheapest-First Is Optimal

Assume all edge costs are nonnegative. Let the next current entry have cost k.

  1. Every other current frontier entry has cost at least k.
  2. Extending any such route cannot make it cheaper: added cost is at least zero.
  3. Any not-yet-found cheaper route would have a frontier prefix with cost less than k, contradicting the minimum choice.

The node’s cost is final when its current entry is removed. In particular, an accepted goal has optimal cost.

Use induction over finalized nodes. If a cheaper path to u existed, consider its first unfinalized node x. Its finalized predecessor would already have relaxed the edge to x, giving x a frontier entry no more expensive than that path’s prefix. Nonnegative edges bound this prefix below the alleged cheaper total, so x would have been removed before u. Do not claim every discovered cost is optimal.

Negative Edges Break That Argument

The queue first contains G:2 and A:5.

UCS removes the goal at cost 2.

But the route through A costs

5+(-4)=1.

A more expensive prefix can now lead to a cheaper solution.

Nonnegative includes zero. Negative edges require a different shortest-path method, such as Bellman-Ford.

This is a directed acyclic graph, so the issue is not a negative cycle. Bellman-Ford can handle negative edges and detect reachable negative cycles; finite shortest paths require the relevant routes not to benefit from such cycles. Do not turn this into a second algorithm lesson.

Completeness Depends on the Search Space

Search setting What ensures UCS eventually finishes?
Finite graph Nonnegative costs and proper duplicate handling. Zero-cost edges are allowed.
Potentially infinite search space Finite branching and a positive lower bound c(u,v)\ge\epsilon>0, with a finite-cost goal.

An infinite chain of zero-cost actions could keep UCS busy forever, while a goal with cost 1 waits in the frontier.

Optimality of a returned goal and eventual discovery of a goal are different guarantees.

What Does UCS Spend Time On?

  • Exploring many low-cost alternatives before the goal becomes cheapest.
  • Maintaining a priority queue, rather than a first-in, first-out (FIFO) queue.
  • Remembering best costs, parents, and pending entries.

For an Explicit Finite Graph

Let V be the number of vertices and E the number of edges. For the duplicate-entry binary heap used in the pseudocode:

Resource Bound
Time O\big((V+E)\log(V+E)\big)
Extra storage O(V+E), including stale heap entries

Assume adjacency lists, nonnegative weights, constant-time dictionary access, and strict improvements. Each node is expanded at most once and each outgoing edge is checked once; each edge can cause at most one insertion during its source’s expansion. An indexed heap with decrease-key and one live entry per vertex instead yields O((V+E) log V) time and O(V) auxiliary storage. Avoid applying the explicit-graph bound to an exponentially large implicit state space.

UCS and Dijkstra: The Same Engine

One Target: UCS

Stop when a current goal entry is removed. Return its route and cost.

Every Reachable Target: Dijkstra

Remove the goal-return condition and continue until the queue is empty. Return all best distances and parents.

Destination Distance from S
S 0
B 2
A 3
C 4
G 6

This is single-source shortest paths, not shortest paths between every pair of nodes.

Dijkstra can also be implemented with early stopping for a target; the names do not imply fundamentally different algorithms. In this small graph G happens to be the last distinct node removed, so all displayed distances are finalized by then. In a larger graph, stopping at G can leave other nodes tentative or undiscovered. Replace the final failure return with best and parent when adapting the pseudocode to Dijkstra.

Another Idea: Search from Both Ends

  • Search forward from the start and backward from the goal.
  • The backward search generates predecessors: states that can lead to the current state.
  • A connection gives a candidate route by joining the two paths.

For unit costs, layer-by-layer bidirectional BFS can find a shortest route without searching all the way from one side.

The diagram is a unit-cost chain with undirected edges. Backward BFS traverses the same links; for directed graphs it must reverse the original transitions, not simply follow outgoing edges from the goal. Each side retains parent information for reconstruction. A correct layer-based bidirectional BFS checks intersections between the reached sets while controlling layer order; do not generalize an arbitrary first meeting to weighted search.

When Does Two-Ended Search Help?

With branching factor b and solution depth d, a balanced search suggests:

\underbrace{b^d}_{\text{one direction}} \quad\text{versus}\quad \underbrace{2b^{d/2}}_{\text{two directions}}.

Requirement Why it matters
A known goal, or manageable goal set The backward search needs a starting point.
Efficient predecessor generation Reversing actions may be difficult.
Suitable stopping rule With weights, the first meeting need not be the cheapest route.

The savings are a useful tree-like estimate, not a guarantee for every graph.

Check Your Understanding

A goal enters the queue with cost 20. Can we stop?

No. Another pending route may reach it more cheaply. Test the goal after removing its current entry.

Are zero-cost edges forbidden?

No, not on a finite graph with proper duplicate handling. An infinite zero-cost region can prevent progress toward a positive-cost goal.

If all edges cost 3, will UCS beat BFS in solution cost?

No. Every depth-d route costs 3d, so both minimize the number of edges. Equal-cost routes can differ.

Takeaways

  • Priority: expand by cumulative path cost g, not depth.
  • Updates: a discovered node can receive a cheaper route.
  • Stopping: accept the goal on its current cheapest removal.
  • Guarantee: nonnegative costs make finalized costs optimal.
  • Connection: Dijkstra continues the same search for all reachable destinations.

The frontier holds possibilities. Removal, not discovery, certifies the cheapest one.
