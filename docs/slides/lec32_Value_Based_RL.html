Learning from Experience

Reinforcement learning (RL) learns how to act from rewards. Model-free methods learn values or a policy without constructing an explicit transition-and-reward model.

A sample (s,a,r,s') records the current state, action, observed reward, and next state.

Learning uses these samples, not a supplied table of transition probabilities or expected rewards.

The delivery setting continues Lecture 30. Diagrams explain the setting to the class; the learner is not given its complete dynamics. A simulator may generate samples without exposing its transition table to the algorithm. Model-based RL can instead learn such a model and plan with it. This does not mean model-free methods lack learned representations. Original public-domain robot: https://openclipart.org/detail/325644/toy-robot. Background: the supplied Spring 2025 Value-Based RL Beamer lecture and https://inst.eecs.berkeley.edu/~cs188/textbook/rl/rl.html.

A Delivery Episode

A policy \pi is an action rule. First evaluate a fixed policy: pick up at depot D, then deliver from stop J.

An episode is one run ending at terminal state F. Its later value is zero: the task has finished.

The return G_t totals future rewards. The discount factor \gamma weights each later reward by another factor. Use \gamma=0.9:

G_0=-1+0.9\cdot8=6.2,\qquad G_1=8.

All rewards are fictional points. The small-job and return choices from Lecture 30 remain available, but the first prediction example follows the fixed pickup-then-deliver policy. Reward r_(t+1) arrives after the action at step t: r1=-1, r2=8. The +8 is received on entry to F; it is not also a terminal-state value. This two-transition episode is deterministic for easy arithmetic, not empirical robot data. After termination all further rewards and bootstrap values are zero.

What a State Value Predicts

The state value V^\pi(s) is expected return when starting at s and following policy \pi:

V^\pi(s)=\mathbb E_\pi[G_t\mid s_t=s].

\mathbb E_\pi averages over outcomes under that policy. Write V(s) for the learner’s current estimate, which may be wrong.

Starting estimates for the comparison D: depot J: pickup stop F: terminal
V(s) 0 4 0

Policy evaluation, also called prediction, estimates how well a given policy does. It does not yet change which actions the policy selects.

The initial estimates are stipulated, not values obtained by planning or earlier updates in this lecture. The exact fixed-policy values in this deterministic example are 6.2 at D, 8 at J, and 0 at F. The learner must estimate them from samples. We compare Monte Carlo and one-step TD using separate copies of this same initial value table. State values concern accumulated future reward, not merely the next reward. Lowercase s_t denotes the state observed at time t; the conditioning notation has its usual random-variable interpretation.

Monte Carlo: Use the Complete Return

Monte Carlo (MC) evaluation learns from complete sampled returns. Wait for the episode to end so G_t is known, then move the estimate toward it:

V(s_t)\leftarrow V(s_t)+\alpha[G_t-V(s_t)].

The learning rate \alpha controls the adjustment size. We use \alpha=0.5: move halfway toward the target.

For the completed delivery episode, G_0=6.2 and the old V(D)=0.

V(D)\leftarrow0+0.5(6.2-0)=3.1. This is one update, not the exact value after learning has finished.

We use constant-step-size Monte Carlo prediction. A sample-average variant uses alpha=1/N on the Nth relevant return. For this route D and J each occur once, so first-visit and every-visit distinctions do not affect the example. J also updates from 4 toward its full return 8, yielding 6. MC uses no bootstrapped value in its target; stochastic long episodes can make full returns noisy. We do not claim that a finite constant-step-size estimate is unbiased or already converged. Source: supplied Beamer MC material, with the delivery example made explicit.

Temporal-Difference Learning

Temporal-difference (TD) learning updates after a transition. Bootstrapping means using an existing estimate to help construct another estimate’s target.

For one-step TD(0), observe reward r_{t+1} and next state s_{t+1}:

y_t=r_{t+1}+\gamma V(s_{t+1}),\qquad \delta_t=y_t-V(s_t).

Here y_t is the target and \delta_t is the TD error: target minus current estimate.

V(s_t)\leftarrow V(s_t)+\alpha\delta_t.

One observed reward plus an estimated future value lets TD learn before the episode ends. For a terminal next state, the target is just r_{t+1}.

The fixed-policy Bellman identity is V^pi(s)=E_pi[r_(t+1)+gamma V^pi(s_(t+1)) | s_t=s]. TD samples a transition and substitutes its current V for the unknown true future value. This explains both sampling and bootstrapping without requiring a transition model. TD(0) is a one-step method; the zero refers to the lambda=0 endpoint, introduced later, not to a zero-step return. Reference: https://inst.eecs.berkeley.edu/~cs188/textbook/rl/mfl.html and the supplied Beamer TD frames.

Same Episode, Different Update Timing

Start both methods from V(D)=0, V(J)=4, V(F)=0, with \gamma=0.9 and \alpha=0.5.

When delivery then gives 8 and ends the episode:

MC: update V(D) to 3.1. TD: leave V(D)=1.3 for now. Both update V(J) to 4+0.5(8-4)=6.

For chronological one-step TD, the D update happens before the reward 8 is observed, using the old V(J)=4. Its target is -1+.9*4=2.6 and new value 1.3. At J the next state is terminal, so the second target is 8 and V(J) becomes 6. Ordinary one-step TD does not automatically revisit D at the end; it can propagate J’s improved value on a later visit. MC’s D update waits for the completed return and reaches 3.1 from its own untouched initial value. These are two different estimators on separate value tables, not sequential updates to one table.

TD(0): One Transition

Follow the fixed policy \pi. The environment reports whether sNext is a terminal next state.

function TDUpdate(s, r, sNext, terminal)
if terminal: target = r
else: target = r + gamma * V(sNext)
delta = target - V(s)
V(s) = V(s) + alpha * delta

If the robot receives 8 on entering F, should its target be 8+0.9\cdot8?

No. The target is 8. The delivery reward has already been received; V(F)=0 prevents counting it twice.

The function updates a shared current V table, with gamma and alpha supplied as learning parameters. The terminal flag means true task termination, not merely that a program stops collecting samples at an arbitrary time limit. A time-limit truncation can require bootstrapping if the underlying task continues. Do not reset to the new episode’s start state before constructing this transition’s target. No terminal action is chosen.

From Prediction to Control

Control improves the action rule, rather than only evaluating a fixed one. An action value Q(s,a) estimates return after choosing a at s and following the policy being evaluated afterward.

A tabular method stores one number per state-action pair. Both methods below update toward a target y:

Q(s,a)\leftarrow Q(s,a)+\alpha[y-Q(s,a)].

At D, a small job finishes immediately; pickup goes to J. A greedy choice takes the largest current Q: if these estimates are 4 and 0, it chooses the small job.

Epsilon-greedy explores with probability \epsilon by choosing uniformly among all available actions; otherwise it is greedy.

The table is still an estimate. Exploration can collect evidence about an action whose current estimate is too low.

For fixed-policy prediction the formal target is Q^pi(s,a)=E_pi[G_t | s_t=s,a_t=a]. A control method updates values while improving its action rule. SARSA evaluates the policy used for behavior, while Q-learning uses an optimality target; this distinction follows on the next slides. This Q table is separate from the state-value V table in the MC/TD comparison. At D we set Q(small)=4 and Q(pickup)=0; at J the upcoming comparison sets Q(deliver)=6 and Q(return)=1. These are arbitrary current estimates, not exact solutions. Epsilon-greedy can select its greedy action during exploration too, as in Lecture 31. Random tie breaking is used if several actions share the largest estimate.

Behavior and Target Policies

The behavior policy generates actions. The target policy is the action rule whose return is being learned.

  • On-policy: learn about the same policy used to act.
  • Off-policy: the target policy can differ from the behavior policy.

At J, deliver finishes the job; return goes back to D. After pickup gives -1, the robot reaches J and explores by selecting return:

This is a different experience from the earlier fixed pickup-then-deliver episode: after reaching J the behavior policy selects return. The first pickup at D can also be exploratory under the displayed Q table. For the next two numerical updates, start independently from Q(D,pickup)=0, Q(J,deliver)=6, Q(J,return)=1, gamma=.9, and alpha=.5. Off-policy is about the relationship between behavior and target, not a promise that the target is already good or that exploration is unnecessary. SARSA’s name and Q-learning are introduced on their own slides, not in an unexplained list of algorithms.

SARSA: Use the Selected Next Action

SARSA names the sample it uses: State, Action, Reward, State, Action, or (s,a,r,s',a'). The next action a' is the one actually selected by the behavior policy.

y=r+\gamma Q(s',a')=-1+0.9\cdot1=-0.1.

Start from Q(D,\text{pickup})=0 and \alpha=0.5:

Q(D,\text{pickup})\leftarrow0+0.5(-0.1-0)=-0.05. SARSA is on-policy: its target includes the exploratory return action.

The shared action-value update is Q(s,a) <- Q(s,a)+alpha[y-Q(s,a)]. The observed tuple for this update is (D,pickup,-1,J,return). We have selected the next action; SARSA need not wait for return’s subsequent reward to make this update. In an online loop that chosen action must then be executed, rather than silently resampled after the update. For a terminal next state no next action is selected and y=r. The negative estimate is possible because pickup incurs a cost and the current estimate for the exploratory continuation is low. It is not the true optimal return of the task. Reference: the supplied Beamer SARSA frame; Sutton and Barto, second edition, Section 6.4.

Q-Learning: Use the Largest Next Estimate

Q-learning learns action values using a greedy target, even if behavior chooses an exploratory action. Here a' ranges over available actions at s'.

y=r+\gamma\max_{a'}Q(s',a')=-1+0.9\max\{6,1\}=4.4.

Use the same starting Q(D,\text{pickup})=0, not SARSA’s updated value:

Q(D,\text{pickup})\leftarrow0+0.5(4.4-0)=2.2. Q-learning is off-policy: its target uses deliver, although behavior chose return.

This is an alternative update from the same initial table and the same observed transition as SARSA, not a second update following it. The immediate observed reward remains -1; using max does not replace a sampled immediate reward with an imagined one. Q-learning targets optimal action values Q, but a finite current Q table is not Q. The method does not require that the behavior actually take the maximizing action at J for this update. For a terminal successor the target is r, with no max over terminal actions. Reference: https://inst.eecs.berkeley.edu/~cs188/textbook/rl/mfl.html; supplied Beamer Q-learning material; Sutton and Barto, second edition, Section 6.5.

A Tabular Q-Learning Loop

Start a fresh run. Q(s) denotes the row of estimates for actions available at state s.

Q = 0 for every available state-action pair
for each episode
s = StartState()
while s is not terminal
a = EpsilonGreedy(Q(s), epsilon)
(r, sNext, terminal) = Step(a)
target = r
if not terminal: target += gamma * max(Q(sNext))
Q(s, a) += alpha * (target - Q(s, a))
s = sNext

StartState resets the task. Step executes the chosen action and returns its reward, next state, and terminal flag.

The action used for behavior can be exploratory; the nonterminal learning target still uses the largest next estimate.

Gamma, alpha, and epsilon are chosen learning parameters; epsilon-greedy includes every available action in its random branch. We distinguish this fresh zero-initialized run from the arbitrary current table in the preceding worked comparison. The update is in place for only the observed state-action pair. Do not take a max over an empty terminal-action set or bootstrap from the next episode’s reset state. The loop is intentionally tabular; it is not a neural-network or replay-buffer algorithm.

Deep Q-Networks: From Tables to Networks

A deep Q-network (DQN) replaces a Q table with a neural network Q_\theta(s,a), where \theta denotes learned weights. DQN uses Q-learning, but not all Q-learning is DQN.

  • Experience replay: store past transitions and train on randomly sampled batches.
  • Target network: a separate, periodically refreshed network supplies bootstrap estimates, helping stabilize learning.

Volodymyr Mnih et al. (2015), Human-level control through deep reinforcement learning, Nature.

Earlier paper: Volodymyr Mnih et al. (2013), Playing Atari with Deep Reinforcement Learning.

DQN stands for deep Q-network, also used to name the associated algorithm/agent. Q-learning is the broader method: it can use a table or a function approximator. Canonical DQN uses a trained online network, stored transitions for uniform experience replay, and a separate target network whose weights are held fixed between periodic copies. At a terminal transition the target remains just r. The network is fitted to targets with gradient-based updates rather than directly overwriting an individual table entry. Its shared weights can change predictions for several states/actions. The diagram shows only actions available at D; a full implementation must respect state-dependent action availability. It is a schematic, not a trained network or performance result. The original Atari work used a fixed set of game actions and image inputs. References are shown on the slide at first introduction: Mnih et al. (2013), https://arxiv.org/abs/1312.5602, and Mnih et al. (2015), https://doi.org/10.1038/nature14236. The 2015 paper’s first three, equally contributing authors are Volodymyr Mnih, Koray Kavukcuoglu, and David Silver.

Common DQN Variants and Extensions

Variant or extension Main idea
Double DQN Select the next action with the trained network; evaluate it with the target network. This reduces overly optimistic estimates.
Dueling DQN Learn state value and action advantage, an action’s score relative to that baseline, then combine both into Q estimates.
Prioritized experience replay (PER) Replay transitions with larger TD errors more often; corrective weights compensate for unequal sampling.
Rainbow Combine several DQN improvements rather than choosing just one.

Double DQN changes target action selection, not just the number of networks. These extensions can be combined.

The names link to primary papers. Double DQN: Hado van Hasselt, Arthur Guez, and David Silver, Deep Reinforcement Learning with Double Q-learning, AAAI 2016 (preprint 2015), https://arxiv.org/abs/1509.06461. Unlike standard DQN’s maximum over the target network’s own values, Double DQN selects a maximizing next action with the online network and evaluates that selected action with the target network. Dueling: Ziyu Wang, Tom Schaul, Matteo Hessel, Hado van Hasselt, Marc Lanctot, and Nando de Freitas, Dueling Network Architectures for Deep Reinforcement Learning, ICML 2016 (preprint 2015), https://arxiv.org/abs/1511.06581. The two streams are combined with an identifying normalization, typically subtracting the mean action-advantage output; a raw stream output should not be mistaken for an independently identified exact Q-minus-V. PER: Tom Schaul, John Quan, Ioannis Antonoglou, and David Silver, Prioritized Experience Replay, ICLR 2016 (preprint 2015), https://arxiv.org/abs/1511.05952. Importance-sampling weights correct the changed sampling distribution; partial correction is often annealed. Rainbow: Matteo Hessel et al., Rainbow: Combining Improvements in Deep Reinforcement Learning, AAAI 2018 (preprint 2017), https://arxiv.org/abs/1710.02298. It combines Double DQN, dueling architecture, prioritized replay, multi-step learning, distributional returns, and noisy-network exploration. These are established examples, not claims about the latest or universally best algorithm. PER is a replay extension, not a separate synonym for Q-learning.

Multi-Step Returns

An n-step return uses n observed rewards, then an estimated continuation:

G_t^{(n)}=\sum_{k=0}^{n-1}\gamma^k r_{t+k+1}+\gamma^n V(s_{t+n}).

Here n=1,2,\ldots and k indexes the rewards. At termination, stop and use no future value.

TD(0) uses n=1. More observed rewards require waiting longer.

Return to the original pickup-then-deliver episode and the original V(J)=4 for this horizon comparison. The bootstrapped value is a current estimate when the target is formed. The displayed formula applies when n transitions are available before or at termination; at termination V(F)=0. A general implementation truncates n at the remaining episode length. Larger n reduces dependence on a possibly inaccurate bootstrap estimate but adds sampled-reward variability; it is not universally better or a universal monotonic bias/variance theorem. Background: supplied Beamer n-step material and Sutton and Barto, second edition, Chapter 7.

TD-Lambda: Blend Return Horizons

TD(\lambda) mixes different return horizons. The parameter 0\leq\lambda\leq1 controls how much weight longer returns receive.

For our two-step episode, the blended target is exactly:

G_0^{(\lambda)}=(1-\lambda)\,2.6+\lambda\,6.2.

\lambda Target in this example Interpretation
0 2.6 One-step TD target
0.5 4.4 Equal mix of the two horizons
1 6.2 Complete episode return

The zero in TD(0) refers to \lambda=0, not to observing zero rewards. Longer episodes blend more than two horizons.

This is the episodic forward-view lambda-return using the original estimates, not a claim that every online accumulating-trace update is identical to this fixed-target calculation. For H remaining transitions, the finite episodic weights are (1-lambda)*lambda^(n-1) for n=1,…,H-1 and residual lambda^(H-1) on the full return. They sum to one and correctly give the complete return at lambda=1. We deliberately avoid substituting lambda=1 into an unqualified infinite expression with prefactor 1-lambda. The target 4.4 at lambda=.5 coincides numerically with the earlier Q-learning target but arises from a different construction. References: Sutton and Barto, second edition, Chapter 12; https://www.davidsilver.uk/wp-content/uploads/2020/03/MC-TD.pdf.

Eligibility Traces: Remember Recent States

An eligibility trace e(s) is a temporary weight tracking recent visits. It lets a new TD error adjust earlier states too.

Start traces at zero for each episode. Before each update, decay all traces by \gamma\lambda, then add 1 to the current state’s trace.

Use the current TD error \delta_t to update every state:

V(s)\leftarrow V(s)+\alpha\delta_t e(s).

This is accumulating tabular TD(lambda): compute delta from pre-update V, set all e(s) <- gammalambdae(s), increment e(current) by 1, then update all V(s) using that same delta. After D then J without revisits, e(D)=.9*.5=.45 and e(J)=1. These are trace weights, not action probabilities; with repeated visits accumulating traces can exceed one. Reset traces at each true episode boundary, not after every transition. The diagram illustrates credit assignment without asserting that standard online traces exactly match an arbitrary frozen-value forward return; exact online forward/backward equivalence requires the appropriate true-online method. Background: supplied accumulating-trace Beamer material, Sutton and Barto Chapter 12, and https://arxiv.org/abs/1512.04087.

Checks for a Learning Implementation

  • Terminal target: use only the observed final reward, not a value from the next episode.
  • Correct continuation: SARSA uses the selected next action; Q-learning uses the largest next estimate.
  • Enough exploration: an untried action can remain badly estimated, even with an off-policy method.
  • Learning rate: \alpha=0.5 makes our arithmetic easy; a fixed learning rate does not guarantee exact convergence in a noisy task.

Tabular Q-learning’s convergence guarantees rely on repeated state-action visits and suitable learning rates. They are not guarantees for arbitrary behavior or arbitrary neural-network updates.

The usual finite discounted tabular Q-learning theorem assumes bounded rewards, every state-action pair updated infinitely often, and per-pair step sizes whose sum diverges while their squared sum converges, along with the standard sampling conditions. State-dependent action sets must be respected. Fixed epsilon may preserve exploration but does not make a SARSA behavior policy greedy in the limit. The goal here is to prevent overgeneralizing the original statement that off-policy learning works regardless of behavior, not to prove a convergence theorem. Function approximation can introduce separate stability issues.

Quick Check

  1. After pickup, why can TD update V(D) while MC waits?
  2. Behavior chooses return at J. Which next estimate do SARSA and Q-learning use: 1 or 6?
  3. If entering F gives reward 8, what is the one-step target?

1. TD uses the observed -1 plus the current estimate for J. MC needs the episode’s complete return.

2. SARSA uses 1, for return. Q-learning uses 6, the largest next estimate, for deliver.

3. 8. There is no future return after the terminal state.

Takeaways

  • MC waits for complete returns; TD bootstraps after a transition.
  • State values evaluate a policy; action values help improve choices.
  • SARSA uses the selected next action; Q-learning uses a greedy target.
  • DQN uses a neural Q-network, experience replay, and a target network.
  • Multi-step returns and TD(\lambda) combine longer experience with estimates.
  • Eligibility traces distribute a TD error across recently visited states.

Always identify the observed reward, the estimated continuation, and the policy that continuation represents.
