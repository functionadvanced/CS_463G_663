Same Minimax Value, Less Search

Pruning means skipping unexplored branches once we can prove they cannot improve the root’s decision.

Minimax checked all 9 leaves. Can we establish the same root value, 3, with less work?

Recall that MAX seeks the highest score and MIN the lowest, always using MAX’s viewpoint. This is exactly the example from Lecture 9, not a new game. Alpha-beta pruning preserves the minimax root value for the same tree and leaf evaluations. Equally optimal root moves can differ when move ordering or tie-breaking changes. Source: AIMA adversarial search chapter and the original Lecture 10 Beamer source.

A Branch We Can Stop Searching

Search depth first, left to right. Leaf numbers are terminal scores, measured from MAX’s viewpoint.

At A: \min(3,12,8)=3. MAX already has an option worth 3.

At B: seeing 2 proves B\le2. Skip its remaining leaves: MAX can choose A.

At C: check 14, 5, then 2. Root value 3, move A, only 7 of 9 leaves evaluated.

Before revealing each step, ask which player controls the node. After inspecting B’s first leaf, its eventual minimum can only stay at 2 or decrease. Therefore it cannot beat A’s exact value 3. Only the unvisited children of B are pruned; C must still be searched. At C, neither 14 nor 5 is low enough to stop, and the final 2 arrives after all its leaves have been examined. Crosses replace unevaluated leaf values. We know only B <= 2 from this search, even though the fully specified example’s true B value is 2. The returned bound is sufficient to reject B. Source: AIMA minimax example, extended with an alpha-beta trace.

Alpha and Beta: Options Already Available

  • \alpha (alpha): MAX’s best lower bound so far along the search path.
  • \beta (beta): MIN’s best upper bound so far along the search path.
  • Start at the root with \alpha=-\infty, \beta=+\infty. Pass the current bounds to each child.

At B, MAX already has 3 elsewhere, so \alpha=3.

MIN finds a reply worth 2, lowering \beta to 2.

Prune when \alpha\ge\beta.

A cutoff can return a bound, not an exact subtree value. Here, knowing B\le2 is enough.

Alpha and beta describe alternatives on the active path, not the global largest and smallest leaves. At a MAX node the current best child raises alpha. At a MIN node the current best child lowers beta. The bounds are passed downward by value; they are not reset at every node. Alpha can only increase and beta can only decrease during one call. If the interval closes, an ancestor already has an option at least as good, so remaining siblings cannot improve its decision. Equality also permits pruning when seeking one optimal root action. On a cutoff, a MIN return is an upper bound and a MAX return is a lower bound on that subtree’s true minimax value. Only the full-window root result is necessarily exact. Source: AIMA alpha-beta algorithm.

A Cutoff at a MAX Node

Now the root is MIN. It can already choose A for 5. At B, MAX discovers a child worth 8.

Could B’s remaining child make MAX’s choice smaller than 5?

No. B\ge8, but MIN can keep 5. At B, \alpha=8\ge\beta=5, so skip the remaining child.

Emphasize the swapped root role. A is a MAX node with leaves 1 and 5, so its exact value is 5. That completed option provides the inherited beta bound for B. No matter what B’s unseen child contains, MAX at B can keep at least 8. MIN above will avoid it. This is the symmetric counterpart of the earlier MIN-node cutoff. All utilities still use MAX’s viewpoint. Original course example.

Alpha-Beta Pseudocode: MAX

AB searches state s; a is a legal action. Start with AB(root, -infinity, +infinity). This is the MAX case.

AB(s, alpha, beta)
if TERMINAL(s): return UTILITY(s)
if PLAYER(s) == MAX:
v <- -infinity
for a in ACTIONS(s):
child <- RESULT(s, a)
v <- max(v, AB(child, alpha, beta))
alpha <- max(alpha, v)
if alpha >= beta: break
return v

MAX raises alpha. break skips the remaining actions at this node, then returns to the parent.

This is the MAX case of the same AB function whose MIN case follows. TERMINAL asks whether the game is finished, UTILITY gives the terminal score, PLAYER gives the side to move, ACTIONS lists legal actions, and RESULT produces the successor state including its player. The state carries the turn, so no separate Boolean flag is needed. The local variable v is the best returned child score so far. Each child receives the current bounds. Values are passed by value, not through shared global variables. At the root, additionally retain the action when a child strictly improves the best score, as in Lecture 9. This slide searches to terminal states; a later slide adds a depth cutoff. Source: AIMA algorithm, rewritten in the notation of Lecture 9.

Alpha-Beta Pseudocode: MIN

The MIN case of the same function. RESULT(s, a) is the state reached by taking action a in state s.

AB(s, alpha, beta)
if TERMINAL(s): return UTILITY(s)
if PLAYER(s) == MIN:
v <- +infinity
for a in ACTIONS(s):
child <- RESULT(s, a)
v <- min(v, AB(child, alpha, beta))
beta <- min(beta, v)
if alpha >= beta: break
return v

MIN lowers beta. Both branches use the same stopping test: \alpha\ge\beta.

Compare the two cases: infinity, min/max, and the updated bound change; recursion and the stopping test stay the same. A cutoff return can be a bound rather than an exact value, which the calling algorithm handles through its own bounds. A nonterminal position must have a successor, including a legal pass where the rules require one. In HW2, neither player having a legal move is terminal; one player having no move is a pass. Keep the score from a fixed root-player viewpoint rather than switching perspective with every recursive call.

Quick Check: When Can We Stop?

MAX already has 4 from A. At MIN node B, the first leaf gives 6. Can we stop? What if the next leaf gives 3?

After 6, continue: 4<6. After 3, prune: \alpha=4\ge\beta=3. MAX keeps A, worth 4.

The values printed at untouched leaves are given problem data, not evaluations already performed. Ask for the comparison before revealing the answer. If the second leaf were exactly 4, equality would also allow pruning. If it were 5, we would still need the final leaf. Changing the skipped leaf to any number cannot make B exceed 3. The exact value of B could decrease further, but MAX’s root choice stays A. Original course exercise.

Move Ordering Changes the Work

Move ordering means trying promising moves first: high scores at MAX, low scores at MIN.

At C, try 2 before 14 and 5.

Search Leaves checked
Plain minimax 9
Original order 7
Better reply order 5

With branching factor b and depth d, worst-case time is still O(b^d). Ideal ordering can reduce it to O(b^{d/2}).

Ordering changes which move we try first. Alpha-beta decides which remaining moves can safely be skipped.

Keep root order A, B, C and A’s replies unchanged. B still visits 2 first. Reorder C’s original replies 14,5,2 to 2,14,5, so C’s first reply closes the window. The visited leaf count is 3+1+1=5. We do not know exact child values in advance in real games; heuristics or earlier search results suggest an ordering. Best-case complexity describes balanced trees with ideal ordering, not a guaranteed practical runtime. Worst ordering can give little or no pruning. The root value remains 3; ties may change which equally optimal move is selected. Source: AIMA alpha-beta analysis.

A Depth Limit Changes the Leaf Scores

Let d count the remaining plies, where one ply is one player’s move. At a depth limit, the game may still be unfinished.

AB(s, d, alpha, beta)
if TERMINAL(s): return UTILITY(s)
if d == 0: return EVAL(s)
# Otherwise use the same MAX / MIN branches.
# Each move calls AB(child, d - 1, alpha, beta).
  • UTILITY(s): exact score of a finished game.
  • EVAL(s): an estimate for an unfinished position, using the same player’s viewpoint.

With identical cutoffs and scores, alpha-beta matches depth-limited minimax. The heuristic estimate may still miss the best move in the full game.

Always check terminal before the depth cutoff. Alpha-beta is exact relative to the leaf scores supplied to it; it does not make inaccurate heuristic scores accurate. The demo notebook has explicitly supplied terminal leaves and no depth parameter. HW2 uses a function named utility for its board evaluation at both terminal and depth-limited states, so its name alone does not imply the position is terminal. Time Limits and Unstable Positions

Iterative deepening

Search depths 1, 2, 3, …. Keep the best move from the last completed search if time runs out. Its move ordering can help the next search.

Quiescence search

“Quiescent” means quiet or stable. Near a cutoff, extend selected forcing moves, such as a capture and immediate recapture, before evaluating.

Forward pruning skips moves because a heuristic judges them unpromising. Unlike alpha-beta’s bound test, it can change the minimax answer.

If depth 1 chooses A, depth 2 chooses B, and depth 3 is interrupted, use B from the completed depth-2 search. A partial deeper search has not compared every relevant root alternative. An implementation also needs a legal fallback if even the first iteration cannot finish. Quiescence addresses the horizon effect: a depth boundary may hide a forcing reply that reverses a seemingly good score. It usually extends a limited set of tactical moves and needs its own limits; it is not an instruction to search indefinitely until all play is calm. These are practical extensions, not extra HW2 requirements. Source: original Lecture 10 topics and AIMA adversarial search.

Takeaways

  • Alpha-beta uses bounds to skip work while preserving the minimax root value.
  • MAX raises \alpha; MIN lowers \beta. Stop remaining siblings when \alpha\ge\beta.
  • Better move ordering can produce more pruning.
  • A depth cutoff needs a heuristic estimate and a consistent score viewpoint.
