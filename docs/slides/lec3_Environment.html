Task Environments

An agent’s environment determines what information is available, how actions matter, and how hard decision-making becomes.

Seven Environment Dimensions

  • Single agent vs. multi-agent
  • Episodic vs. sequential
  • Static vs. dynamic
  • Fully observable vs. partially observable
  • Deterministic vs. stochastic
  • Known vs. unknown
  • Discrete vs. continuous

Which side of each contrast usually makes the agent’s job easier?

Agent Structure

First ask whether the agent is alone.

Single Agent vs. Multi-Agent

Single Agent

  • Everything else in the environment can be treated as an object.
  • Other entities do not strategically react to the agent.

Multi-Agent

  • Other entities should be viewed as agents.
  • Their actions may depend on what our agent does.
  • Agents may be competitive or cooperative.

Multi-agent settings add strategic uncertainty: other agents can adapt.

Time and Consequences

Next ask whether the current decision affects future decisions.

Episodic vs. Sequential

Episodic

  • Current action does not depend on choices in previous episodes.
  • Current action does not affect future episodes.
  • Example: classifying one independent image.

Sequential

  • Current action can affect future states and future choices.
  • The agent may need planning.
  • Example: driving, chess, tutoring.

Static vs. Dynamic

Static

  • The environment changes only when the agent acts.
  • No need to worry about time passing.

Dynamic

  • The environment can change while the agent is deciding.
  • The agent must keep up.

Semidynamic

  • The world does not change by itself.
  • The performance score changes with time.

Information Available

Now ask how much of the relevant state the agent can observe.

Fully Observable vs. Partially Observable

Fully Observable

  • Every relevant piece of information is available on demand.
  • The agent does not need to track hidden state.

Partially Observable

  • Some relevant information is missing.
  • Causes:
    • limited sensors
    • malfunctioning sensors
    • noisy sensory data
    • hidden variables

Outcome Uncertainty

Next ask whether actions have predictable outcomes.

Deterministic vs. Uncertain

Deterministic

  • Given the current state and action, the next state is determined.
  • There is no randomness in the outcome.

Uncertain

  • The next state cannot be determined with full confidence.
  • Causes include partial observability and unpredictable action outcomes.

Stochastic vs. Nondeterministic

Stochastic

  • The model explicitly uses probabilities.
  • Example: “There is a 25% chance of rain tomorrow.”

Nondeterministic

  • Possible outcomes are listed without probabilities.
  • Example: “There is a chance of rain tomorrow.”

Model Knowledge

Known vs. unknown refers to the agent’s knowledge of the environment rules.

Known vs. Unknown

This distinction refers to the agent’s knowledge about the “laws of physics” of the environment.

  • Known: the rules of the environment are known in advance, even if the rules are stochastic.
  • Unknown: the rules are not known and must be learned.

An environment can be fully observable but still unknown if the agent does not know how actions work.

State and Action Granularity

Finally, ask whether states, time, and actions come in distinct units or vary smoothly.

Discrete vs. Continuous

Discrete

  • State, time, and actions can be divided into clearly labeled classes.
  • Example: chess board positions and legal moves.

Continuous

  • State, time, or actions vary smoothly.
  • Example: steering angle, speed, position, time.

Putting the Dimensions Together

The seven labels form a compact description of the agent’s task environment.

Takeaways

  • Environment properties determine what an agent must handle.
  • Fully observable, deterministic, static, discrete tasks are easiest.
  • Real-world tasks are often partially observable, dynamic, multi-agent, and continuous.
  • The same task can be classified differently depending on assumptions.
  • Good agent design starts with a clear task-environment analysis.
